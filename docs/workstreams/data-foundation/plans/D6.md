## Design contract

### D1 Held-out discipline

**D1.1 Attempts record** `tests/fundamentals/fixtures/data_foundation/stage4_holdout.yaml`,
append-only (a committed entry never changes; checked against its introducing commit):

```yaml
attempts:
  - n: 1
    identifier: <NSE symbol>            # the only plaintext company value in the repo
    selection:
      seed_commit: <full SHA>           # attempt 1: the commit recording the approved plan;
                                        # attempt k>1: the burn commit of attempt k-1
      selection_commit: <full SHA>      # HEAD of the selector's checkout; record_n's parent
      as_of: <date>                     # Asia/Kolkata date of the frame's retrieved_at (D1.3)
      frame: {url, sha256, retrieved_at, column: Industry, excluded_values: [...]}
      exclusion_inventory_sha256: ...   # sorted (symbol_sha256, reason) lines
      universe_sha256: ...              # sorted eligible-universe symbol lines
      n_universe: <int>
      catalogue_exemptions: [{path, sha256}]   # D1.2 amendment
      start_index: <int>
      skips: [{index, symbol_sha256, reason: NOT_EQ|NON_IN_ISIN|NO_CONSOLIDATED_INCAPMKT|XBRL_NOT_ADMITTED|BSE_NOT_ONE|TOKEN_HIT, evidence_sha256}]
      selected_index: <int>
    prediction: {capability_commit, capability_sha256, outcome, excluded_units, diagnostic_excluded, run_status}
    approval: {reviewer: gpt-6.1-sol, verdict: APPROVE, date, payload_sha256}
burns:                                   # appended by Q2 only
  - {attempt: 1, reason_code, bead, freeze_descriptor_sha256, date}
```

`payload_sha256` = SHA-256 of the attempt mapping without `approval`,
`yaml.safe_dump(sort_keys=True)`; validated per attempt, independent of the Stage 1/2 helper.

**D1.2 Universe (C9).** Frame: NSE Nifty 500 constituent CSV (URL and `Industry` column confirmed
in Task 0b; absent → halt). The selector runs on a clean checkout whose `HEAD` is
`selection_commit` (descendant of `seed_commit`); the orchestrator commits the record directly on
it, so `record_n^ == selection_commit` and the scanned revision cannot be stale. Exclusions, in
order: `Industry` ∈ pinned financial values (at least `Financial Services`); any token hit (D1.6
matcher, tokens = symbol, ISIN, normalised name of each frame row) in
- every blob and tree reachable from `selection_commit` (`git rev-list --objects
  selection_commit`, read by `git cat-file --batch`: deleted, renamed, merge-only and binary
  content included — development use that was later deleted still excludes);
- every untracked or ignored file at selection under `src/ config/ tests/ migrations/ scripts/
  docs/ scratchpad/` (`git ls-files --others`, with and without `--exclude-standard`);
- every directory name under `data/` to depth 2, except `data/holdout/`.
**Catalogue exemptions** — exactly two untracked files, each exempt only while its bytes match the
pinned SHA-256 (any other content at that path, or any other location, is scanned normally):
`scratchpad/upstox/entity-map-v2/entity_map.json` (
`9f61287c82e46244b0823a5fac25da7313a5d0ba39c325b434139ce5aafbbc2a`) and
`scratchpad/upstox/entity-map-2026-09-04/entity_map.json`
(`c2f81973797cb4d362c76061c41dd7d17579ba244ebf20f28119ef0c23c911f7`), whole-market Upstox
instrument→entity maps. They are skipped in both this scan and the D1.3 `TOKEN_HIT` rescan; every
other location still excludes on any hit, and D1.6 is unchanged. The attempt's `selection` records
`catalogue_exemptions: [{path, sha256}]` (in the payload), and private copies of both files are

Nothing was selected and no entry was written, so nothing was burned. Attempt 1 is redrawn with

run's outputs are kept in `data/holdout/attempt-1/run-1/`.
Universe = remaining symbols sorted by ASCII bytes; the inventory is hashed. Private selection bytes
live in gitignored `data/holdout/attempt-<n>/` (names carry no identifier); no development input
reads that path.

**D1.3 Draw.** `seed = sha256(f"{seed_commit}:{frame_sha256}:{n}".encode("ascii"))`,
`start_index = int(seed.hexdigest(), 16) % n_universe`; walk `i = (start_index + j) % n_universe`,
`j = 0..n_universe-1`; select the first candidate passing every rule, each read from retained bytes
under `data/holdout/attempt-<n>/`: `NOT_EQ` (no `EQ` row in pinned `EQUITY_L.csv`), `NON_IN_ISIN`,
`NO_CONSOLIDATED_INCAPMKT` (the **filing-window rule** below yields fewer than two distinct
period ends), `XBRL_NOT_ADMITTED` (attempt 3 on, amendment 2026-10-16: the two latest
qualifying period ends' instances fail the XBRL prefilter — D4.3 `financial_rule` of both before
either is parsed, the `ONBOARDING_VERSIONS` schema, then each instance's `instance_state` and
`framework_state`; issuer identity, name and report-nature declarations are not prefiltered and
are left to discovery), `BSE_NOT_ONE` (`PeerSmartSearch` by ISIN has not
exactly one exact-ISIN candidate), `TOKEN_HIT`. A fetch failure **halts** the draw (reported opaque), so failures cannot steer
selection. The seed proves non-steering, not secrecy. Retained eligibility responses are trusted as
captured.

**Filing-window rule (C11, C13)** — one rule, used by selection, discovery (D4.2 step 2) and the
holdout checker: given an `as_of` date, the window is the six latest calendar quarter-ends on or
before `as_of`; rows of both NSE listings (legacy and integrated) with period end in the window
collapse to the latest broadcast per `(period_end, basis)` (equal broadcast times: selection skips
`NO_CONSOLIDATED_INCAPMKT`, discovery gives `IDENTITY_CONFLICT`); qualifying filings are the
collapsed consolidated `in-capmkt` rows, counted by **distinct period end**. `as_of` is never the
wall clock at evaluation: selection uses `selection.as_of`, discovery the discovery manifest's
`as_of` (D2), and replay reuses it.
Clarification (orchestrator ruling 2026-10-16, Task 1b; reviewed in Task 5b): a qualifying row is
an integrated-listing row of type `Integrated Filing- Financials` with consolidated basis; legacy
rows join the collapse but never qualify; rows without a basis (e.g. Governance) are outside the
collapse; a `(period_end, basis)` group containing a row with no broadcast time does not qualify
(no fallback ordering field). Selection, the holdout checker and discovery share this reading.
Clarification (orchestrator ruling 2026-10-16, attempt 2): each NSE listing is one request, the
response as served (observed, not guaranteed: the integrated listing serves 20 rows, newest period
first, and `totalCount` may exceed them). Selection, the checker and discovery read the same single page; a
`totalCount` above the served rows is not a fetch failure and does not halt the draw. Pagination is
follow-up work, not part of D6.

**D1.4 Prediction rule.** Input: the capability table committed in Task 0b
(`docs/workstreams/data-foundation/d6-capability.md`, one YAML block mapping each unit to
`reachable` or `excluded: <ruling|evidence>`). `excluded = {u : not reachable}`;
`diagnostic_excluded = excluded ∩ {UPSTOX}`; `outcome = ONBOARDED if not excluded else PARTIAL`;
`run_status = INCOMPLETE if excluded − {UPSTOX} else COMPLETE`. An unreachable anchor halts the
plan. With probe evidence every attempt predicts `PARTIAL`, `[RESULTS_PDF]`, `[]`, `INCOMPLETE`.
The checker recomputes this from the committed table.

**D1.5 Ordering.** `IMPL = src/ config/ migrations/ scripts/ pyproject.toml uv.lock`.
- Attempt 1: no commit in `seed_commit..record_1` touches `IMPL`; `record_1^ == selection_commit`;
  `record_1` is a strict ancestor of `src/fundamentals/entity/discovery.py`'s first commit and
  every later `IMPL` commit; at the parent of the first `IMPL` commit after `record_1`, attempt 1
  carries `APPROVE` with a matching payload hash.
- Attempt k>1: `seed_commit` = the commit appending burn k−1; `record_k^ == selection_commit`
  descends from it; the freeze descriptor for k descends from `record_k` and cites its payload hash.
- Every attempt: entries ≤ k and burns are byte-equal to their introducing commit; only the last
  unburned attempt is current.
Checkers take a repo path; a `tmp_path` git repo covers initial ordering, one burn/refreeze/redraw
cycle, and four violations (`IMPL` commit before `record_1`; record edited after commit; `IMPL`
change after freeze; `record_1^ ≠ selection_commit`).

**D1.6 Leak scan (C10).** Tokens of the current attempt = NSE symbol, ISIN, BSE scrip, normalised
name, derived inside the checker from the private selection bytes — never written to the repo.
Match: bytes, ASCII case-insensitive, neighbours not `[A-Za-z0-9]`, name words joined by `\s+`
after removing trailing `Limited|Ltd.?`. Scope: every object `git rev-list --objects
selection_commit..HEAD` lists under `src/ config/ tests/` (blobs and trees, so transient, renamed,
merge-resolution-only and binary content and every entry name are read via `git cat-file
--batch`), plus the current tree and untracked files under those roots. Exempt:
`stage4_holdout.yaml`, `stage4_manifest.yaml` (a blob is exempt only if `git ls-tree -r HEAD` shows
its id at no other path). Mutations: alternate token (ISIN), token in a file name, token in a binary
blob, token added then deleted, token introduced only in a merge resolution and later deleted.

**D1.7 Opaque outputs.** Selector and record-reviewer briefs write only the attempt entry and
`data/holdout/attempt-<n>/` and return only PASS/FAIL, payload hash, skip count and reason codes.
Holdout checks fail with `pytest.fail(msg, pytrace=False)` naming the check (and path for leaks),
never `assert` on values. The orchestrator commits the record by explicit path and stamps Sol's
approval with a throwaway script that verifies the hash and prints nothing. The identifier never
enters a brief, bead, commit message, plan or scratch note before the freeze; any pre-freeze
disclosure is a burn.

### D2 Acquisition and replay

One path: `fundamentals onboard <symbol> --raw-root <dir> --snapshot-root <dir> [--acquire
--freeze-descriptor <path>] [--generation <n>]`. The fetch is a `Callable` parameter of `discover`;
`--acquire` wraps the real transports, replay reads the retained root.

- **Generations.** `<raw-root>/gen-<n>/` is immutable once written; a re-run writes `gen-<n+1>`;
  replay uses `--generation` or the highest complete one.
- **`discovery-manifest.json`** (sibling of the package manifest, probe Q5 option b):
  `{issuer, authorization, generation, as_of, entries: [{request_key, source_id, surface, unit,
  url, filename, sha256, bytes, retrieved_at, outcome}]}`; `as_of` = Asia/Kolkata date of the
  `EQUITY_L` entry's `retrieved_at` (the first request), the only date the filing-window rule
  reads (C13); `request_key` = `surface|` + sorted `k=v` parameters; `outcome` ∈ `OK`,
  `HTTP_<code>`, `TIMEOUT`, `NOT_AUTHORISED` (failures retained). Replay refuses a duplicate or
  missing key, a missing file, a SHA mismatch or an `as_of` not derivable by that rule, and never
  opens a socket.
- **Package manifest** `retrieval-manifest.json` in the existing intake format (`issuer`,
  `authorization`, entries with `quarter`, `kind: xbrl-consolidated`, `nse/` folder), XBRL only, so
  `retained_intake_from_manifest` needs no change (no PDF member → no issuer config, probe Q5).
- **`acquisition.json` (C5)**: `{generation, attempt, freeze_descriptor_sha256, descriptor_commit,
  acquisition_head, implementation_commit, argv, discovery_manifest_sha256,
  retrieval_manifest_sha256}`. With `--acquire`, before any request, `onboard` refuses unless:
  `git status --porcelain -- IMPL <descriptor path>` is empty; `HEAD`'s blob of the descriptor
  file holds attempt k's entry with the given SHA-256 (so the entry is committed, not merely
  supplied); `descriptor_commit` = the first commit whose descriptor blob holds that entry, and
  it is an ancestor of (or equal to) `HEAD`; `implementation_commit` (from the entry) is an
  ancestor of `descriptor_commit`; `git diff --quiet <implementation_commit> HEAD -- IMPL`. It
  records `acquisition_head = HEAD`. Acquisition therefore runs on the descriptor commit or a
  descendant, never by checking out `implementation_commit`.
- **Request inventory** (bounded, every entry authority-checked first, D4.4): NSE `EQUITY_L.csv`;
  NSE `financial_results` and `/integrated-filing-results`, retained raw, all bases (new
  `ingest/nse_filings.py`); the two consolidated XBRL instances via `NseXbrlSource`'s download and
  verification; BSE `PeerSmartSearch` by ISIN via urllib with the probe's browser headers, raw HTML
  (not the `bse` library); Screener search API and the consolidated company page
  (`screener_session`); Tijori search API and financials page (`tijori_source`); Upstox instrument
  file and, separately, the authenticated consolidated `income-statement` request.
- **Credentials and redaction.** Existing transports keep their redaction and host checks; the
  fetch envelope records URL without query secrets and never stores headers.

**D3.2 Writers** (`entity/identity_layers.py`, under `pg_advisory_xact_lock` on
`(namespace, value)` and `(target, namespace)`):
- Intervals are half-open `[valid_from, end)`, `end` = `effective_date` of the event whose `ENDS`
  edge names the relationship. Active at `as_of` iff started on/before and not ended on/before.
  `as_of=None` = the store's current date (future-effective events allowed, not yet current).
- `record_relationship` is idempotent for a value equal to the target's current one and refuses
  (`IdentityConflictError`) a different value for the same `(target, namespace)` or the same
  `(namespace, value)` on another target with an overlapping interval. A D1a base value becomes a
  relationship on demand (citing its seed input, `valid_from` null) when an event must end it.
- `record_event` writes event, edges and any started relationship in one transaction, enforcing:
  `ISIN_CHANGE` ends one security `ISIN` and starts one on the **same** security; `SYMBOL_CHANGE`
  the same for one listing's `NSE_SYMBOL` or `BSE_SCRIP`, ended and started namespace equal, and
  refused if the new value was ever held by another listing; `SYMBOL_REUSE` is that change for a
  value whose every relationship on another listing ended on/before `effective_date`; `DELISTING`
  ends ≥1 of one listing's relationships, starts none; `MERGER` ≥1 `PREDECESSOR`, exactly 1
  `SUCCESSOR`; `DEMERGER` exactly 1 `PREDECESSOR`, ≥1 `SUCCESSOR`; predecessor ∩ successor = ∅.
  Chronology: `effective_date` ≥ each ended relationship's start; a started relationship's
  `valid_from` = `effective_date`.
- **Legacy aliases (replaces R3-1's member-identity edit, C3).** `record_event` refuses
  `ISIN_CHANGE`/`SYMBOL_CHANGE`/`SYMBOL_REUSE` on a security whose ISIN is a key of
  `ACCEPTED_ENTITY_IDS_BY_ISIN` (`ingest/xbrl_identity.py:26–28`): that legacy rename is already
  encoded by the registry, which `verify_xbrl_identity` applies unconditionally
  (`member_identity.py:107`); refusing the event keeps the two mechanisms disjoint without editing
  the pinned verifier.

- No hits → new entity. Its key is the verified NSE symbol if no `reporting_entities` row has that
