**Goal:** storage scales with coverage: every capture has a retention class; a dry-run lists
exactly the eligible blobs; an explicit, lock-guarded, crash-safe purge deletes them, tombstones
vendor payload and keeps outcomes; an expired exchange original restores only by a hash-matched
re-fetch; replay over expired vendor readings reports `ORIGINAL_EXPIRED`; backup and restore
never resurrect expired bytes, and a vendor licence end purges that vendor's material.
**Out of scope:** scheduled purge (P5); retention exception contracts and physical memory removal;
vendor blob compression; off-machine backups; backfilling addresses of pre-D9 exchange captures
(they stay `KEEP`, R14); deleting operator input files outside the snapshot store, and set copies
outside the backup directory (Risks); automatic re-ingest after a re-fetch mismatch; D8
shareholding intake; any change to a file whose content an extractor pin hashes (R13).
**Constraints:**
- Migrations forward-only; `0001`–`0026` immutable; D9 adds `0027`–`0030`.
- Approved amendment records, frozen manifests, `record.json` files and `capture_refs` rows are
  never rewritten. The only in-place change D9 makes to evidence rows is the purge role's vendor
  tombstone, which ledger §6 item 4 authorises.
- The runtime role still cannot delete; only `eqos_purge` purges, and only through the purge path.
- Fetchers, purge crash points and reviewer calls are the only mocks; no network in tests.
- Manifest values come from a throwaway `scratchpad/` aid that never imports `fundamentals`.
- Never open, grep or print `stage4_holdout.yaml`, `stage4_manifest.yaml`, `data/holdout/` or
  `data/raw/onboarding/`; no code path or test added here reads them (R4).
- Strict mypy, ruff, frozen Pydantic, enums, structlog; every module traces to a stage
  acceptance or a Verify cell; 800-line cap per file (File map).

## Rulings (proposed; Sol approves with the plan)

- **R1 Paths and dependency direction.** Roadmap `migrations/0009_retention.sql` →
  `0027_retention_classes.sql` (D9.2), `0028_retention_protocol.sql` (D9.4),
  `0029_retention_purge.sql` (D9.5), `0030_retention_refetch.sql` (D9.6). D9.1 does **not** extend
  the approved, digest-pinned `2026-10-12-report-ledger.md`; new records
  `docs/blueprint/amendments/2026-10-12-retention-replay.md` and
  `docs/blueprint/amendments/2026-10-12-a05-derived-amounts.md`. Direction (acyclic):
  `contracts/retention.py` (enums, errors, report models) ← `pg` (`pg/retention_io.py`: session
  locks and the backup-directory authority files; `backup.py`) ← `evidence/capture_retention.py`,
  `retention/*` ← `api/*`. `pg` never imports `retention`, `evidence` or `compare`: restore takes
  purge-first as an injected callable and `retention.purge` takes the final backup as one; the
  API layer composes both (`api/db_cli.py`, `api/retention_cli.py`). `compare` imports only
  `contracts`. The orchestrator edits the roadmap row when recording this plan.
- **R2 Classes.** One source of truth, in SQL: `eqos.base_class(source_id, surface)` returns
  `VENDOR` for every surface of a vendor source (`eqos.is_vendor_source`: `screener`,
  `screener-subscriber`, `tijori`, `upstox`) except Upstox `instruments` (`IDENTITY`); `IDENTITY`
  for non-vendor identity surfaces (NSE `EQUITY_L` and listings, BSE peer search, SHP listing);
  `EXCHANGE_REFETCHABLE` for `NSE_XBRL_INSTANCE`, `NSE_RESULTS_PDF`, `NSE_TRANSCRIPT_PDF`,
  `NSE_SHP_XBRL`; `COVERED` for any other non-vendor original ("not filed on an exchange"); else
  raises `UNCLASSIFIED`. An `AFTER INSERT` trigger on `capture_refs` writes the class row (cause
  `INTAKE`), so every registration path classifies without Python changes; a second class row is
  refused. Pre-D9 captures are classified once by `eqos.classify_existing()` (cause `ONE_OFF`)
  through `fundamentals retention classify`; purge and dry-run refuse while any capture is
  unclassified. **Coverage (P3) is derived, never stored:** an `EXCHANGE_REFETCHABLE` capture is
  effectively `COVERED` when an entity linked to it (`eqos.capture_entities`) has an `ADD` not
  followed by a `REMOVE` before the capture's registration (P1 precedent: derived from the
  decision log). `RETENTION_LIMITED` is likewise a view, `eqos.retention_limited`: each ADD
  decision × the entity's linked `VENDOR`/`IDENTITY` captures registered before it.
- **R3 Retention = class rule, then source ceiling.** Eligibility first applies the class rule
  (R5), then caps it with the source's catalog ceiling. Ceiling for vendor-bounded sources
  (`is_vendor_source`): four quarters from registration, extended only by open queue items, and
  never past a recorded licence end. Upstox instrument lists are `IDENTITY` by class, but their
  source ceiling is the Upstox record's "retain what an open investigation needs"
  (`upstox-rights-record.md:172,259`): an identity event may reference one, without extending it
  past the ceiling. Non-vendor sources have no ceiling (rights decision 004). "Beyond catalog
  authority" is refused at the database boundary (RP3c, d): any capture-referencing write for a
  licence-ended source, and a `SOURCE_QUOTE` claim on a vendor capture. Supports, onboarding
  outcomes and identity events referencing vendor captures are accepted and do not extend them.
  One test pins `eqos.is_vendor_source` to the sources of catalog surfaces whose role is
  `INDEPENDENT_VENDOR` or `DIAGNOSTIC`.
- **R4 Citation graph.** Hold roots, and the edges the hold query follows to a capture:
  report versions → `numeric_claims` (quote capture; interpretation; calculation trace →
  `calculation_trace_operands`, recursively; fact origin → imported: legacy binding, native:
  `fact_admissions` occurrence/interpretation), `COMPARISON` claim → `pair_outcomes` →
  `result_source_values` → interpretation or trace, and `report_sections.body` location markers;
  memory items and supports (direct capture, claim, version, disposition → item); queue items and
  dispositions (`queue_item_inputs`, `queue_item_traces`; `OPEN_QUEUE_ITEM` when undisposed);
  legacy bindings; identity events, onboarding records and namespace verifications through
  `evidence_input_captures`; admitted native facts; qualification fixture sets (SHA-256s from
  `config/mappings/**`); frozen manifest inputs (`config/retention/holds.yaml`, public manifests
  only; `stage4_manifest.yaml` is excluded by name, never read, and a test pins the list to the
  public `*_manifest.yaml` glob). Every interpretation reached closes over
  `interpretation_operands`, `interpretation_condition_evidence` and `construction_traces` down
  to occurrences → capture. Run manifests and outcomes never hold. Edges that **need bytes**:
  `SOURCE_QUOTE` claims, location markers, legacy bindings. Every table above that creates an edge
  carries the guard (RP3).
- **R5 Eligibility** (pure, unit-tested), in order: licence end reached → `ELIGIBLE(since=licence
  end)`, holds notwithstanding; effective `COVERED` → `KEEP`; relevant holds → `HELD(reasons)`,
  where relevant = any root for non-vendor-bounded sources and open queue items only for
  vendor-bounded ones (R3); then the anchor. `EXCHANGE_REFETCHABLE`: anchor = verification time,
  `KEEP` without a recorded address; `VENDOR`/`IDENTITY`: registration. No anchor → `KEEP`;
  `now` before anchor + window → `KEEP`; else `ELIGIBLE(since)`, with reason `CATALOG_CEILING`
  when a hold was set aside by R3. Windows: three calendar months (P4), four quarters (twelve
  months), clamped to month end. **Verified** = the earliest `COMPLETE` run with a `SELECTED`
  `PACKAGE` input for the capture's package and no undisposed queue item referencing any capture
  of that package; time = the later of that run's `created_at` and the last disposition of those
  items. A **blob** is `(source_id, blob_sha256)` over captures not `EXPIRED`; it is eligible only
  when every user is, `since` the latest. `now` is `eqos.store_now()`; tests advance a test
  database's `eqos.store_clock_us` as its owner; production has no as-of flag.
- **R6 Retention protocol (RP).** Stated once; every task and the table below refer to it.
  - **RP1 Lock.** One advisory key, `eqos.retention_lock_key()`. Purge holds it exclusive at
    session level on a dedicated, non-pooled connection from the step-2 recheck through run close
    (recovery the same). Backup holds it shared at session level from before its snapshot export
    through archive verification. Everything else takes it shared at transaction level through
    `eqos.retention_shared()`, which refuses while any intent is `PURGE_PENDING` or a run is open
    (naming `fundamentals retention purge`), then applies RP2. There is no isolation exception
    and no session flag.
  - **RP2 Stale-snapshot check.** Sequence `eqos.retention_epoch`: `USAGE` for `eqos_purge` only,
    `SELECT` for others. Every purge invocation, under the exclusive lock, commits a `purge_runs`
    row carrying `nextval` in its first committing transaction. After taking the lock,
    `retention_shared()` compares `pg_sequence_last_value` (not MVCC) with the greatest
    `purge_runs.epoch` its snapshot sees. Unequal → refused `STALE_SNAPSHOT` (retry). READ
    COMMITTED statements see the purge commit after waiting and pass; a REPEATABLE READ or
    SERIALIZABLE transaction passes only if its snapshot follows every purge, so D2's SERIALIZABLE
    writers need no change and nothing is forgeable. A rolled-back `nextval` fails closed until
    the next purge commits a run; the refusal names the purge command.
  - **RP3 Database boundary.** One trigger function, `eqos.retention_guard()` (attached as
    `a0_retention_guard`, `BEFORE INSERT FOR EACH ROW`), on every edge table of R4 plus
    `capture_refs`, watchlist `ADD` decisions, and the payload tables `occurrences`,
    `interpretations`, `interpretation_operands`, `interpretation_condition_evidence`,
    `construction_traces`, `calculation_trace_operands`, `result_source_values`, `run_inputs`,
    `acquisition_attempts`, `package_members`. It calls `retention_shared()`, resolves the row's
    captures through the R4 edge, and refuses (a) a payload row whose capture is not
    `RETAINED`/`RESTORED` → `ORIGINAL_EXPIRED`; (b) a byte-needing edge to such a capture →
    `ORIGINAL_EXPIRED`; (c) any row whose capture's source has a `licence_ends` row, including
    `capture_refs` → `BEYOND_AUTHORITY`; (d) a `SOURCE_QUOTE` on a vendor capture →
    `BEYOND_AUTHORITY`. Other edges to an expired capture proceed (ledger §5: they resolve to the
    record and tombstones). The guard never reads `store_now()`, so `lock_queue` stays legal after.
  - **RP4 Store boundary.** (a) `licence-end` first writes a marker
    `<root>/.retention/licence-ended/<source>` under the writer flock; while it exists,
    `put_capture`, `get_capture` and `read_capture_verified` for that source raise
    `LicenceEndedError` (a `SnapshotError`), so no publisher or re-extraction of that vendor can
    proceed, with or without a database. (b) Purge holds the writer flock from its first unlink in
    step 3 until its step-4 transaction commits, so no publication lands between deletion and
    `EXPIRED`. Lock order is always database lock, then flock; store-only publishers take only the
    flock. No cycle.
  - **RP5 Unregistered captures.** Step 3 compares the blob inode's link count with its
    registered links; a surplus (a standalone publication, or a crash between publication and
    registration) is `UNKNOWN_LINK`: that blob's intents are cancelled, its bytes stay, and the
    purge reports `INCOMPLETE` with the blob and exits 3. This repeats on every purge until the
    operator registers or removes the capture. A licence-end purge instead deletes the source's
    whole capture and blob trees, registered or not; if any file there has links outside those
    trees, it refuses before deleting anything (exit 2), so a licence end never completes with
    bytes left.
  - **RP6 Identity, not bytes.** `ORIGINAL_EXPIRED` concerns an expired capture row. A new
    acquisition of equal bytes is a new capture (ledger §6: "a fresh fetch is a new capture"):
    registration republishes the blob, and the expired capture stays `EXPIRED` with no body link.
    First-party SHA-256 reuse matches retained captures only. Re-fetch is the only way back for
    the expired capture itself.
  - **RP7 Byte readers** go through `read_retained` (`EXPIRED`/`PURGE_PENDING` →
    `OriginalExpiredError`; missing body otherwise → `IntegrityError`, corruption).

  | Publisher or reader | Protocol |
  |---|---|
  | Discovery and first-party registration (`capture_registration`) | RP1 first statement → blob lookup → `put_capture` (RP4) → insert (RP3c); reuse per RP6 |
  | Vendor registration (`ingest_vendor` → `put_capture_ref`) | RP3 on `capture_refs`; RP7 pre-check in `ingest_vendor_retained`; RP4a |
  | Standalone acquisition (Upstox, Tijori, local originals) | RP4, RP5 |

  | Ledger, memory, queue, watchlist, fact admission, legacy writes | RP3b–d (R4 edges) |

  | Backup | RP1 session shared; R12 |
  | Restore | R12 (target closed to all other roles) |

- **R7 Tombstones (A-05).** A vendor capture's payload is tombstoned **in place**; rows stay
  because outcomes, queue inputs and run inputs reference them. Task 1 audits every column and
  JSON path the three vendor adapters and their derived traces and result rows write, and the
  A-05 record fixes the resulting **redaction inventory**: kept = id, capture id, key columns,
  anchor location, states, `first_seen_at`; cleared = every value-bearing scalar
  (`occurrences.raw_value_text`, `raw_sign` (NOT NULL dropped in 0029); `interpretations.value/
  lower/upper`; value, bound and exact-text columns of vendor-derived `calculation_traces` and
  operands; `result_source_values.value/lower/upper` of vendor and diagnostic roles), and JSON
  columns reduced to an allowlist of non-value keys (never a denylist), so
  `native_context.island_value` goes. `transform_trace` → `{}`. A digest computed over a cleared
  value is itself value-bearing; the inventory lists each, and any a constraint keeps goes to the
  A-05 review as stated residual risk. Kept as outcomes per A-05: results, `pair_outcomes`
  (status, reason, triage, `difference`, `interval_gap`), adjustments, queue items,
  dispositions, `COMPARISON` claims. Only the migrator-owned `SECURITY DEFINER`
  `eqos.tombstone_vendor_capture(capture)`, executable by `eqos_purge` alone and only for a
  `PURGE_PENDING` `VENDOR` capture, performs it; a replacement mutation trigger on the touched
  tables allows an `UPDATE` only under its transaction-local flag and only of inventory columns.
  `DELETE` stays refused everywhere.
- **R8 Purge steps and recovery** (ledger §5 steps 1–5). Order: authority files (R11) read and
  reconciled into the database; candidates; **step 1**: probe up to `PROBE_SAMPLE = 3` eligible
  `EXCHANGE_REFETCHABLE` captures per source (lowest ids first); any mismatch or fetch failure
  halts that source's exchange deletions and records a HIGH probe row (R9). Take the exclusive
  session lock, commit the run row with its epoch (RP2), then **recover**: each `PURGE_PENDING`
  intent is cancelled if its bytes are intact and it is no longer eligible, else it goes through
  steps 3–5; then **residue**: any `EXPIRED` or `PURGE_PENDING` capture whose body link exists,
  and any blob with no non-`EXPIRED` registered user and no unknown link, is deleted again;
  then any open run completes step 5. **Step 2:** recheck eligibility; commit intents for
  still-eligible blobs (exchange ones only from probe-matched sources). **Step 3** under the
  writer flock (RP4b): per blob, unlink each registered body link, then the blob, fsyncing each
  parent; missing = deleted; link surplus → RP5. **Step 4**, one transaction, then release the
  flock: purge records (capture, class, reason, URL or null, blob hash, probe row or
  `NOT_REQUIRED`, `purged_at` from the store clock), `EXPIRED`, and for `VENDOR` the tombstone.
  **Step 5:** append every `EXPIRED` capture missing from `expired-captures.json` (R11); the
  injected final backup runs inside the purge's lock session; then **sanitize**: every published
  set in the backup directory whose archived bodies include a capture in `expired-captures.json`
  is renamed `.<name>.deleting`, the directory fsynced, the tree removed; remnants
  (`.deleting`, `.partial`) are removed; only then the run closes. Every intermediate crash
  leaves the run open, which blocks writers (RP1) until a rerun converges.
- **R9 HIGH incidents.** `queue_items` need a run, measurement key and pair (`0006:55-70`); a
  probe failure or re-fetch mismatch has none. As D6 did for `IDENTITY_CONFLICT` (`0022:43-56`),
  they are rows in `retention_probes` / `refetch_attempts` with `severity = 'HIGH'`, surfaced by a
  derived view `eqos.retention_incidents` with resolution semantics: a probe incident closes on a
  later matching probe for that source; a mismatch incident closes when that capture is
  `RESTORED`, otherwise stays listed. The dry-run prints open incidents; a command that creates
  one exits 3 (as `SUCCESS_WITH_OPEN_HIGH`, `compare/run_models.py:66-72`). Spec text "queues a
  HIGH item" is amended to this in the retention-replay record (Task 1), not silently reread.
- **R10 Re-fetch.** `fundamentals retention refetch --capture <id>` admits only an `EXPIRED`
  capture of a non-vendor-bounded source with a recorded address (else `NOT_REFETCHABLE`); a
  licence-ended source and Upstox instrument lists are therefore refused. `Fetch =
  Callable[[str], bytes]` raises `FetchFailure(category, http_status)` with category `TIMEOUT`,
  `CONNECTION`, `HTTP_STATUS` or `INCOMPLETE` (the live adapter checks Content-Length).
  **Transaction A** (committed before any store write, so failure records survive): a
  `refetch_attempts` row with outcome `MATCH`/`MISMATCH`/`FAILED`, category, status and fetched
  SHA-256 (null unless bytes complete). **MATCH →** transaction B under `retention_shared()`:
  `SnapshotStore.relink` writes the blob and links it as the existing capture's body under the
  writer flock (never `put_capture`, never `record.json`), reads it back verified, then commits
  `RESTORED` (same id and times). The `RESTORED` admission rule requires latest state `EXPIRED`,
  a non-vendor-bounded source, and a `MATCH` attempt for this capture whose SHA-256 equals
  `capture_refs.blob_sha256`. A crash between relink and commit leaves residue: rerunning
  `refetch` completes it, and any purge's residue step (R8) removes it. **MISMATCH** (HIGH): the
  capture stays `EXPIRED`; the fetched bytes become a new capture through `capture_registration`,
  whose request parameters carry the attempt id, so a rerun is idempotent and the pair is
  joinable both ways (invariant 13). **FAILED**: nothing published; exit 2.
- **R11 Authority files.** Two files beside the sets in the backup directory, never inside one:
  `licence-ends.json` (spec) and `expired-captures.json` (source, surface, request key, capture
  id, blob and record SHA-256, `purged_at`, run). One helper in `pg/retention_io.py` updates
  either: flock `.retention-authority.lock`, read, append (an update that drops an entry is
  refused), write temp, fsync, rename, fsync directory. **Initialisation** happens only when
  `write_backup` publishes into a provably new location: both files absent, no other set or
  remnant in the directory, and a database with no `licence_ends` row and no `EXPIRED` capture.
  Otherwise a missing or unreadable file refuses purge, backup, restore and licence-end without
  writing anything. **Reconciliation** at the start of each of those: file entries missing from
  the database are inserted; a database licence end missing from the file refuses (rerun
  `licence-end`). **Licence end** (owner, `VENDOR`-bounded sources only), each step idempotent:
  (1) store marker (RP4a), (2) file append, (3) `licence_ends` row as owner, (4) purge as the
  purge role, holds notwithstanding. A crash after (1) already blocks the source at the store;
  after (2), the next purge, backup or restore reconciles (3); a rerun finishes (4).
- **R12 Backup and restore.**
  - **Backup:** `write_backup` takes `session_shared` (or, with `held=<purge connection>`,
    asserts exclusive), refuses pending recovery and missing authority (R11), archives every
    `RETAINED`/`RESTORED` capture's record and body and **every** capture's `record.json`
    (expired ones record-only through `SnapshotStore.put_record`, each hash-checked against
    `capture_refs.record_sha256`), lists expired captures in `BackupManifest.expired` (capture
    row, URL, purge record id), verifies, publishes, then initialises authority if eligible.
    Absent schema → D2 behaviour unchanged (no lock, no authority); refused backups write
    nothing, so `test_backup_restore.py:193,204` hold as written.
  - **Restore** (test databases only, as today), in order: verify the set; absent schema → D2

    set's parent); create the target **closed from creation** (`CREATE DATABASE ...

    group only, then allow connections; no other session can exist); `pg_restore`; copy archived
    retained captures and every archived record. **Phase 1, before any mutation:** the D2
