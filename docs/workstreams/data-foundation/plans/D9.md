# D9 Retention and Replay Implementation Plan

Status: draft for Sol plan review (written 2026-10-17).

**Origin:** Phase D9 row of [`roadmap.md`](../roadmap.md) (stages D9.1–D9.9, exit, edges
D9 → D2, D3, D4, D6, D7); stages `eqos-4fc.1`–`.9` (acceptance read from bd 2026-10-17). Specs:
[ledger spec](../../../specs/2026-10-12-report-ledger-memory-and-data-lifecycle.md) O9, P3–P5,
§5, §6, amendments 2 and 6, Open Questions (A-05), Success Criteria Stage 5, the 2026-10-15
amendment (single reviewer = panel); [data spec](../../../specs/2026-10-11-canonical-financial-data-and-cross-source-comparison.md)
§6 backup (D2), as amended by ledger §6 items 4–6, 9. Evidence:
[vendor terms](../../../research/vendor-terms-screener-tijori-2026-10.md). Conventions from
[D2](D2.md), [D6](D6.md), [D7](D7.md). D8 is parked; D9 uses only its D8.1 surface registrations.
**Goal:** storage scales with coverage: every capture has a retention class; a dry-run lists
exactly the eligible blobs; an explicit, lock-guarded, crash-safe purge deletes them, tombstones
vendor payload and keeps outcomes; an expired exchange original restores only by a hash-matched
re-fetch; replay over expired vendor readings reports `ORIGINAL_EXPIRED`; backup and restore
never resurrect expired bytes, and a vendor licence end purges that vendor's material.
**Out of scope:** scheduled purge (P5); retention exception contracts and physical memory removal;
vendor blob compression; off-machine backups; backfilling addresses of pre-D9 exchange captures
(R5: they stay `KEEP`); deleting operator input files outside the snapshot store (Risks);
automatic re-ingest after a re-fetch mismatch; D8 shareholding intake.
**Constraints:**
- Migrations forward-only; `0001`–`0026` immutable; D9 adds `0027`–`0030`.
- Approved amendment records, frozen manifests, `record.json` files and `capture_refs` rows are
  never rewritten. The only in-place change D9 makes to evidence rows is the purge role's vendor
  tombstone, which ledger §6 item 4 authorises.
- The runtime role still cannot delete; only `eqos_purge` purges, and only through the purge path.
- Fetchers, purge crash points and reviewer calls are the only mocks; no network in tests.
- Manifest values come from a throwaway `scratchpad/` aid that never imports `fundamentals`.
- Never open, grep or print `stage4_holdout.yaml`, `stage4_manifest.yaml`, `data/holdout/` or
  `data/raw/onboarding/`; no code path or test added here reads them (R4).
- Strict mypy, ruff, frozen Pydantic, enums, structlog; every module traces to a stage
  acceptance; 800-line cap per file (File map).

## Grounding (current state)

- **Snapshot store** (`store/snapshot_store.py`, 723 lines). Layout `<root>/<source>/<surface>/
  <request_key>/<capture_id>/{record.json,body<ext>}` with bodies hard-linked to
  `<root>/blobs/<source>/<sha[:2]>/<sha>` (`:21-26`, `:162-188`). `put_capture` holds the writer
  flock for the whole publication (`:136`, `writer_lock` `:701-723`) and, when the blob already
  exists, compares instead of rewriting (`publish_file` `:662-668`). A read re-verifies body and
  blob (`:254-296`); a missing file raises `MissingSnapshotError` (`:657-658`). The store knows
  nothing of the database, so it cannot tell an expired capture from corruption. There is no
  delete or relink operation.
- **Capture records carry no URL.** `RequestIdentity` is source, surface, request key, method and
  parameters (`contracts/snapshot.py:190-200`); first-party request keys hash representation and
  SHA-256 (`evidence/capture_intake.py:260-264`). The retrieval manifest has each `url`
  (e.g. `data/raw/watchlist/aparinds/retrieval-manifest.json` entries), but
  `RetainedCaptureBinding` drops it (`capture_intake.py:81-90`, `:165-174`). Discovery holds
  `Request.url` (`entity/discovery.py:184-197`) and drops it at registration (`:642-692`).
- **Intake paths.** Three sites register captures, each publishing to the store and then calling
  `EvidenceRepository.put_capture_ref` in a separate transaction (`evidence/repository.py:239-248`):
  `discovery.store_captures` (`discovery.py:658-689`, also the owner's coverage registry path),
  first-party `_registered` with SHA-256 reuse (`evidence/first_party_ingest.py:367-381`), and
  vendor ingest, which reads an already-published capture and then registers it
  (`evidence/vendor_ingest.py:131-159`). Vendor acquisition publishes to the store with no database
  at all, so a published capture can exist unregistered.
- **Evidence tables** are append-only through one shared `eqos.reject_mutation()` trigger on every
  table (`0001_evidence.sql`, the immutability block near its end). `capture_refs`
  (`0001:14-25`) has route, blob and record hashes, `registered_at`, `first_seen_at`, and no state.
  Vendor readings live in `occurrences`/`interpretations` (representation HTML/JSON,
  `0006:4-7`); per-source result values sit apart from outcomes "so a later purge (D9) can delete
  vendor values" (`0001:550-575`), yet `pair_outcomes` reference them by foreign key
  (`0001:578-600`), as do queue inputs (`0006:71-79`), trace operands and run inputs. Rows can
  therefore be redacted, not deleted.
- **Hold-root tables.** Claims with `interpretation_id`, `calculation_trace_id`,
  `capture_ref_id`, fact origin (`0012:56-118`); memory supports (`0016:27-39`); queue items and
  inputs, open = no disposition (`compare/queue.py:179-196`); legacy bindings (`0010:98-106`);
  identity events and onboarding records through `evidence_input_captures` (`0022:21-56`,
  `0001:36-41`); admitted native facts through `fact_admissions.occurrence_id` (`0011:4-18`);
  qualification fixture sets as `fixture_evidence[].capture_sha256` in mapping config
  (e.g. `config/mappings/xbrl/v3/in_bse_fin.yaml:92-95`); frozen manifests' `header.sources[].sha256`.
- **Watchlist.** `eqos.watchlisted(entity)` is the current chain head (`0026:17-21`); ADD/REMOVE
  are owner decisions; drafting triggers take the `WATCHLIST` subject lock (`0026:85-134`). The
  READ COMMITTED guard precedent is `0019:59-69`. D2 legacy import runs SERIALIZABLE and inserts
  bindings (`pg/legacy_import.py:310-311`).
- **Source catalog.** `SurfaceAuthority.retention_authority` is only a document path
  (`contracts/source_catalog.py:77-86`); nothing states a retention period. Upstox is absent from
  `BUILTIN_SOURCES` (`:177-179`) but has diagnostic and identity surfaces (`:284-298`). The Upstox
  record approves private retention with "no indefinite default"
  (`docs/research/upstox-rights-record.md:259`); rights decision 005 covers "retention + internal
  processing + internal derived facts" (`docs/evidence/phase-0a/a-05-rights-decision-005-subscriber-scraping.md:18`).
- **Backup** (`pg/backup.py`, 373 lines). `write_backup` exports a REPEATABLE READ snapshot on an
  admin connection, dumps, then closes that connection before archiving every `capture_refs` row
  (`:142-161`), so no lock could span the archive today. `_inventories_consistent` requires one
  archived capture per `capture_refs` row (`:301-308`). `restore_backup` creates a fresh test
  database (which grants CONNECT to every role, `pg/migrations.py:113-143`), restores, copies every
  capture and optionally replays every run (`:189-250`).
- **Replay.** `replay_run` recomputes from manifest ids and stored rows, never bytes
  (`compare/run.py:160-197`); `execute_run` publishes what `resolve` selects (`:117-157`). A
  tombstoned (NULL) vendor value would silently recompute differently. Vendor sides take the latest
  attempt's capture, no fallback (`compare/vendor_sides.py:4-7`).
- **Ledger reads.** A quote may cite only a non-vendor capture (`ledger/citations.py:5`); a
  `COMPARISON` claim reads `pair_outcomes.difference` (`:85-90`); a `CALCULATION` trace must be
  all first-party (`:323-326`). Tombstoning vendor values therefore changes no claim check.
- **Clock and roles.** `eqos.store_now()` is `max(wall, last + 1 µs)` over sequence
  `eqos.store_clock_us` (`0004:16`, `0005`); `runs.created_at` uses it (`0004:61`). Group roles come
  from `GROUP_ROLES` (`pg/settings.py:46-50`); bootstrap and the test session logins iterate it
  (`pg/migrations.py:85-90`, `tests/fundamentals/pg_support.py:124-147`).
- **Shared tests.** `test_amendment_records.py` hashes each record's item list and requires a
  report naming the digest, `VERDICT: APPROVE` and each id (`:47-83`). The approved report-ledger
  record is pinned to digest `ff12604c…` (`docs/blueprint/amendments/2026-10-12-report-ledger.md:6,80`).
  `test_frozen_manifests.py` (783 lines) maps manifests to e2e files (`:52-59`). The Stage 2 e2e
  lists every post-0011 table (`test_data_stage2_e2e.py:46-48`). `scripts/verify_project.sh:62`
  already names the D9 exit test.

## Rulings (proposed; Sol approves with the plan)

- **R1 Paths.** Roadmap `migrations/0009_retention.sql` → `0027_retention_classes.sql` (D9.2),
  `0028_retention_lock.sql` (D9.4), `0029_retention_purge.sql` (D9.5), `0030_retention_refetch.sql`
  (D9.6). D9.1 does **not** extend `2026-10-12-report-ledger.md`: it is approved and pinned to its
  item digest, so adding items would change an approved artifact. New records:
  `docs/blueprint/amendments/2026-10-12-retention-replay.md` (amendments 2 and 6, data-spec §6
  items 1–12) and the roadmap's `docs/blueprint/amendments/2026-10-12-a05-derived-amounts.md`,
  both named by spec date like the report-ledger record. New modules beyond the roadmap:
  `contracts/retention.py` (shared enums and errors, so `compare` and `pg` never import
  `retention`), `evidence/capture_retention.py` (locked registration and the expiry-aware read),
  `retention/holds.py`. The orchestrator edits the roadmap row when recording this plan.
- **R2 Classes.** The stored class is the **base class**, fixed at intake from source and surface
  and never rewritten: `VENDOR` for every surface of a vendor source (`screener`,
  `screener-subscriber`, `tijori`, `upstox`), except Upstox `instruments`, which is `IDENTITY`;
  `IDENTITY` for non-vendor identity surfaces (NSE `EQUITY_L` and listings, BSE peer search, SHP
  listing); `EXCHANGE_REFETCHABLE` for exchange-filed surfaces (`NSE_XBRL_INSTANCE`,
  `NSE_RESULTS_PDF`, `NSE_TRANSCRIPT_PDF`, `NSE_SHP_XBRL`) of non-vendor sources; `COVERED` for any
  other non-vendor original (the SEBI regulation text, the SHP taxonomy: "not filed on an
  exchange"). Anything else is refused as `UNCLASSIFIED` (fails closed). **Coverage (P3) is
  derived from the watchlist decision log, never stored:** an `EXCHANGE_REFETCHABLE` capture is
  effectively `COVERED` when an entity it is linked to has an `ADD` not followed by a `REMOVE`
  before the capture's registration (on the watchlist at capture time, or added later). P1 is the
  precedent: status is derived from the decision log, not a mutable column. A later ADD, or a
  capture whose entity link appears after intake, needs no rewrite. `VENDOR` and `IDENTITY` are
  never upgraded; an ADD records `RETENTION_LIMITED` for the entity's linked retained captures of
  those classes. Pre-D9 captures get a base class once from `fundamentals retention classify`
  (cause `ONE_OFF`, registration time from `capture_refs.registered_at`). Purge and dry-run refuse
  while any capture is unclassified.
- **R3 Catalog authority.** `VENDOR_SOURCE_IDS` (the four sources above) are **vendor-bounded**:
  four quarters from registration, holds count only if open queue items, and everything ends at a
  recorded licence end. All other sources are unbounded (rights decision 004). "Beyond catalog
  authority" is refused at three points: intake from a source with a recorded licence end; any
  hold-creating write referencing a capture of such a source; a `SOURCE_QUOTE` claim on a vendor
  capture (a permanent hold). A second class row for a capture is refused, so a direct attempt to
  upgrade a `VENDOR` capture fails. Supports and onboarding outcomes that reference vendor captures
  are accepted and do not extend their window. `eqos.is_vendor_source(text)` mirrors
  `VENDOR_SOURCE_IDS`, and one test pins the two as equal.
- **R4 Hold roots.** Hold roots are computed in one SQL query: report versions (every claim's
  quote capture, interpretation, trace operands recursively, imported fact → binding, native fact →
  admission occurrence); memory items and supports (direct capture, claim, version, disposition →
  item); queue items and dispositions (inputs and item traces; `OPEN_QUEUE_ITEM` when undisposed);
  legacy bindings; identity events, onboarding records and namespace verifications through
  `evidence_input_captures`; qualification fixture sets (SHA-256s from `config/mappings/**`); and
  frozen manifest inputs (SHA-256s from the manifests listed in a new
  `config/retention/holds.yaml`). That list holds the public manifests only. `stage4_manifest.yaml`
  is excluded: its inputs are held-out bytes outside any purge root, and held-out discipline forbids
  reading it. A test pins the list against the public `*_manifest.yaml` glob, so new manifests are
  added. Run manifests and outcomes never hold. The covered stock is not a separate root: it acts
  through the class (R2).
- **R5 Eligibility** (pure, unit-tested), in order: licence end reached → `ELIGIBLE(since=licence
  end)`, holds notwithstanding; effective `COVERED` → `KEEP`; relevant holds (vendor-bounded: open
  queue items only; otherwise any root) → `HELD(reasons)`; then the anchor. For `EXCHANGE_REFETCHABLE`
  the anchor is the verification time, and the capture is `KEEP` when it has no recorded address,
  because it could not be re-fetched. For `VENDOR`/`IDENTITY` it is registration. No anchor →
  `KEEP`; `now` before anchor + window → `KEEP`; else `ELIGIBLE(since)`. Windows: three calendar
  months (P4) and four quarters (twelve calendar months), clamped to month end. **Verified** =
  the earliest `COMPLETE` run with a `SELECTED` `PACKAGE` input for the capture's package, and no
  undisposed queue item referencing any capture of that package; the time is the later of that
  run's `created_at` and the last disposition of those items. A **blob** is
  `(source_id, blob_sha256)` over captures not `EXPIRED`; it is eligible only when every user is,
  and its `since` is the latest. `now` is `eqos.store_now()`. Tests simulate elapsed quarters by
  advancing a test database's `eqos.store_clock_us` as its owner (the migrator). Production has no
  as-of flag, and no time is backdated.
- **R6 Retention lock protocol.** One advisory key, `eqos.retention_lock_key()`.
  `eqos.retention_shared()` takes `pg_advisory_xact_lock_shared`. It refuses when any intent is
  `PURGE_PENDING` or a purge run is open (naming `fundamentals retention purge`), and refuses
  isolation other than READ COMMITTED unless the session flag `eqos.retention_session` is set.
  Under READ COMMITTED every statement after the wait sees the committed purge. It is called by:
  (a) `capture_registration` as the first statement of the intake transaction, so the lock spans
  blob lookup, store publication and registration; (b) one trigger, `a0_retention_guard`, on
  `capture_refs`, `evidence_input_captures`, `numeric_claims`, `memory_supports`, `report_versions`,
  `queue_items`, `queue_item_inputs`, `legacy_evidence_bindings` and watchlist `ADD` decisions,
  which then refuses a write needing bytes of a non-retained capture (`SOURCE_QUOTE`, legacy
  binding) or beyond catalog authority (R3); (c) re-fetch. Session level, on a dedicated non-pooled
  connection, is reserved for backup (shared, from before the snapshot export through archive
  verification), purge (exclusive, from eligibility recheck through step 5), and one stated
  exception: D2 legacy import, which is SERIALIZABLE (`legacy_import.py:310-311`). A transaction
  lock taken inside it would follow its snapshot, so it holds the shared lock on its connection
  from just before its transaction to just after commit, with the session flag set. The guard
  never reads `store_now()`, so `lock_queue` stays legal after it. **No deadlock:** purge takes no
  other lock (its HIGH signals are not queue items, R9), and writers' FK `KEY SHARE` locks do not
  conflict with the tombstone's non-key `UPDATE`.
- **R7 Tombstones (A-05).** A vendor capture's payload is tombstoned **in place**. The rows stay,
  because foreign keys from outcomes, queue inputs and run inputs need them. Each row keeps its id,
  capture id, key columns, anchor (location), states, digests and `first_seen_at`, and the purge
  record supplies the rest of the ledger §5 tombstone. Cleared: `occurrences.raw_value_text` and
  `raw_sign` (`raw_sign` loses NOT NULL in 0029); `interpretations.value/lower/upper` and
  `transform_trace` (to `{}`); the value, bound and exact-text columns of vendor-derived
  `calculation_traces` and their vendor-derived operands (traces reached transitively from the
  capture's interpretations); and `result_source_values.value/lower/upper` of vendor and
  diagnostic roles pointing at those interpretations or traces. Kept as outcomes per the A-05
  record: results, `pair_outcomes` (status, reason, triage, `difference`, `interval_gap`),
  adjustments, queue items, dispositions and `COMPARISON` claims. Only the migrator-owned
  `SECURITY DEFINER` function `eqos.tombstone_vendor_capture(capture)` performs it, executable by
  `eqos_purge` alone, and only for a `PURGE_PENDING` `VENDOR` capture. A replacement trigger on those
  five tables allows an `UPDATE` only under that function's transaction-local flag and only when
  every non-redactable column is unchanged. `DELETE` stays refused everywhere.
- **R8 Purge steps and recovery** (ledger §5 steps 1–5). The order is: reconcile `licence-ends.json`
  into the database, compute candidates, then run **step 1**: probe up to `PROBE_SAMPLE = 3`
  eligible `EXCHANGE_REFETCHABLE` captures per source (lowest ids first) at their recorded
  address; any mismatch or failure halts that source's exchange deletions and records a HIGH probe
  row. Then take the exclusive session lock and **recover**: each `PURGE_PENDING` intent is
  cancelled (state back to its previous one) if its bytes are intact and it is no longer eligible;
  otherwise it goes through steps 3–5. Any open run then completes step 5. Next, **step 2**:
  recheck eligibility and commit intents for still-eligible blobs (exchange ones only from
  probe-matched sources) plus an open run. **Step 3:** `SnapshotStore.delete_blob` removes the
  blob and each registered link under the writer flock, treating a missing file as deleted. If
  the surviving inode's link count exceeds the expected links, an **unknown user exists** (an
  unregistered published capture or a concurrent same-bytes publish); that blob's intents are
  cancelled with reason `UNKNOWN_LINK` and its bytes stay. **Step 4**, one transaction: the purge
  record (capture, class, reason, URL or null, blob hash, probe row or `NOT_REQUIRED`, `purged_at`
  from the store clock) and `EXPIRED`, plus the tombstone for `VENDOR`. **Step 5:** the injected
  final backup runs inside the purge's lock session. Then delete every published set in the backup
  directory whose retained captures include a now-`EXPIRED` capture, and every `.partial` remnant;
  then close the run. Crash points after steps 2, 3 and 4 (and after step 5's backup) converge on
  rerun. A restore's purge-first (R11) runs steps 1–4 and closes its run without step 5.
- **R9 HIGH signals.** `queue_items` need a run, measurement key and pair (`0006:55-70`); a probe
  failure or re-fetch mismatch has none. Following D6, which recorded `IDENTITY_CONFLICT` severity
  on its own record (`0022:43-56`), they are rows in `retention_probes` / `refetch_attempts` with
  `severity = 'HIGH'`. Their commands exit 3, as `compare run`'s `SUCCESS_WITH_OPEN_HIGH` does
  (`compare/run_models.py:66-72`).
- **R10 Re-fetch.** `fundamentals retention refetch --capture <id>`, in one READ COMMITTED
  transaction under `retention_shared()`. It accepts only an `EXPIRED` non-`VENDOR` capture with a
  recorded address (else `NOT_REFETCHABLE`), fetches through `Fetch = Callable[[str], tuple[int,
  bytes]]`, and records every attempt in `refetch_attempts` under the capture's real id with the
  fetched SHA-256. On a match, `SnapshotStore.relink` writes the blob and links it as the body of
  the existing capture directory (never `put_capture`, never `record.json`), and the capture becomes
  `RESTORED` with the same id and times. On a mismatch, `REFETCH_MISMATCH` (HIGH) is recorded and
  the capture stays `EXPIRED`. The fetched bytes are retained as a **new** capture through
  `capture_registration` (same route, new capture id, normal class), and the attempt names both
  ids, so point-in-time evidence is not dropped (invariant 13). Intake of bytes equal to an
  `EXPIRED` capture is refused with `ORIGINAL_EXPIRED`, naming the refetch command. Re-fetch is the
  only path back.
- **R11 Restore and licence ends.** `licence-ends.json` sits in the backup directory beside the
  sets, never inside one. `write_backup` creates it as `[]` if absent, so every backup directory
  has one. Recording a licence end (owner) appends to the file (atomic replace, fsync), inserts the
  `licence_ends` row, then runs a full purge, holds notwithstanding. Purge and restore read the
  file first: missing or unreadable → refuse ("startup" = these two commands; there is no daemon).
  Any entry absent from the database is inserted. Restore order: refuse a set whose schema predates
  `0028` (no production set exists: the D2 cutover is owner-gated, `eqos-3zl`); create the
  database; revoke CONNECT from runtime, panel, owner and reader; `pg_restore`; copy retained
  captures; reconcile licence ends; purge-first; check; re-grant through `bootstrap_roles`. A failure
  leaves CONNECT revoked. Restore-time purge rests on eligibility recomputed at restore and on the
  licence file. The later database's purge records are not available to it, so a capture held in
  the older set only by an item that later closed is purged by the next purge, not by the restore
  (stated, not hidden).
- **R12 Replay and new runs.** `replay_run` and `execute_run` raise `OriginalExpiredError` when any
  `SELECTED` input (an interpretation or a capture reference) belongs to an `EXPIRED` or
  `PURGE_PENDING` vendor capture (`eqos.expired_vendor_captures(bigint[])`). Restore reports those
  runs as `replay_expired`, never as mismatches (ledger §6 item 9). First-party-only runs replay
  unchanged over expired exchange originals: occurrences are kept. Vendor re-extraction over an
  expired capture raises `ORIGINAL_EXPIRED` before any read, and records no attempt. A missing body
  on a non-`EXPIRED` capture raises `IntegrityError` (corruption) in `read_retained`.
- **R13 Address.** The re-fetch address is the source URL, recorded once per capture at intake in
  `capture_addresses`: first-party from the retrieval-manifest entry, discovery from `Request.url`.
  Purge records copy it, and backups list it for expired captures. Pre-D9 exchange captures have
  none and stay `KEEP` (R5); invariant 13 outranks storage.
- **R14 Manifest independence (D6 discipline, scaled to the risk).** Kept: a fresh Opus author
  using a `scratchpad/` aid that never imports `fundamentals`; inputs limited to retained fixture
  bytes (hashed), the frozen Stage 1/2 manifests (for package members and run statuses), ledger
  §5/§6, R2–R13 and Task 9's scripted clock; expectations decided by hand from the spec rules
  without running D9 code or reading its output; every fixture bound by path and SHA-256; a Sol
  payload-bound approval committed before the e2e's first commit. Dropped: freeze descriptor,
  burns, held-out draw (D9 makes no claim about unseen companies).
