# D8 Shareholding Filing Source Implementation Plan

Status: draft r2 (Sol r1 REQUEST_CHANGES addressed, see r1 dispositions), awaiting Sol re-review.

**Origin:** the Phase D8 row of [`roadmap.md`](../roadmap.md) (stages D8.1–D8.5, the exit, the edge
D8 → D1b, and "Not edges"); stages `eqos-17r.1`–`.5` (acceptance read from bd on 2026-10-17). Specs:
[data spec](../../../specs/2026-10-11-canonical-financial-data-and-cross-source-comparison.md) §7,
§1 (dimensional aggregation), §3 (source authority), §4 (key, disclosure metadata), §5
(shareholding roles and tables), Success Criteria Stage 3, and the 2026-10-14 Family fixture
amendment (a retained adapter→run family-isolation fixture is required in Stage 3);
[ledger spec](../../../specs/2026-10-12-report-ledger-memory-and-data-lifecycle.md) §6 item 7.
Conventions follow [D6](D6.md) and [D7](D7.md).
**Goal:** the exchange shareholding filing is a registered first-party source. Apar, ETERNAL and
TITAN are captured with explicit instant, category, denominator, share class and completeness,
and their promoter, public and institution aggregates are compared with the real Screener,
Tijori and Upstox (diagnostic) captures, matching a frozen Stage 3 manifest.
**Out of scope:**
- Admitting shareholding facts to the fact store.
- Interpreting or comparing holders or pledges. Holder lists are retained as `THRESHOLDED`
  occurrences only; no holder or pledge mapping exists, vendor or first-party.
- First-party subcategories below B1, B2 and B4. They stay `UNMAPPED` occurrences.
- Screener investor drill-downs.
- Measuring Upstox independence. Upstox stays diagnostic.
- Any `EQUIVALENCE_DEMONSTRATED` shareholding mapping. Three companies are fewer than D3's five,
  and Stage 3 needs only manifest-matched outcomes (spec Stage 3), not trusted cells.
- BSE shareholding filings.
- Retention classes. D9.2 classifies these captures.
- Scheduled or market-wide capture.
- Removing or re-parenting the vendor-shaped v2 category members, which would be a major version.
**Constraints:**
- Migrations are forward-only. `0001`–`0026` are immutable, and D8 plans none (R1). If one is
  forced, it is `0027_shareholding.sql`.
- Source authority is checked before capture and before interpretation. An unregistered surface
  gives `NOT_AUTHORISED` and is never sent.
- Absence is never a value. Nothing is zero-filled, and an absent holder is unknown.
- Models never compute numbers. Manifest values and the probe's consistency arithmetic come
  from `scratchpad/` aids that never import `fundamentals`.
- **Versions are never mutated (R1).** Dictionary v3, every D8 mapping file, set v6 and the
  extractor versions `nse-shp-v1`, `screener-shp-v1`, `tijori-shp-v1` and `upstox-shp-v1` are
  final at their first commit. Config is committed complete in Task 3, after the probe and
  before any D8 ingest or comparison. A later change, phase-end fixes included, takes a new
  version. No D8 task ingests into the persistent `equity_os` database.
- **Pinned sources do not change.** These are not edited: the hashed sources of
  `screener-v1`, `tijori-v4` and `upstox-v2` (`compare/run_config.py:80-120`, including
  `evidence/vendor_ingest.py`), and those of the results XBRL and PDF extractors
  (`run_config.py:55-73`, including `evidence/member_identity.py`). The Stage 1 manifest pins
  them.
- **Existing run identities are unchanged.** A default-family request serialises and hashes
  byte-identically to HEAD `70647c0`, and Stage 1/2/4 replays stay green.
- Dependencies point api → components → contracts. Transports are constructed only in `api/`,
  and components take an injected `Fetch`.
- Line caps (800) hold for every touched module (File map). `entity/discovery.py` (800) gets
  in-place edits only, net 0 lines, and `compare/engine.py` (795) stays ≤ 800.
  `test_frozen_manifests.py` (783, plus up to 5 from D7.5) stays ≤ 798.
- Tests make no network request (socket guard on replay). Credentials are read only through
  `scripts/credentials.sh` at run time and are never printed or written.
- Held-out discipline applies. Only development companies are used, and the paths in Constraints
  of D6/D7 are never opened.
- Code uses strict mypy, ruff, frozen Pydantic models, enums and structlog. Every module traces
  to a stage acceptance.

## Grounding (current state)

- **Catalog.** `BUILTIN_SOURCES` has no shareholding source. `VENDOR_SURFACES` registers role and
  retention authority per `(source, surface)` (`contracts/source_catalog.py:177-274`).
  `surface_authority(source, surface, table=)` raises `SurfaceNotAuthorisedError`. In response,
  `ingest_vendor` stores a `NOT_AUTHORISED` attempt (`evidence/vendor_ingest.py:126-136`), and
  `acquiring_fetch` logs `NOT_AUTHORISED` without sending (`entity/discovery.py:317-337`).
  `discovery.authorised` checks a surface against the `ORIGINS` table (`:127-139`, `:276-286`).
- **Dictionary.** Each version is a complete directory, and v2 is the current one (Stage 1 pins v2
  and mapping set v4; set v5 is the latest). The v2 `shareholding.yaml` declares four rows
  (`shp_holding_pct`, `shp_promoter_pledged_pct`, `shp_num_shareholders`, `shp_holder_pct`), all
  with `basis_applicability: [CONSOLIDATED, STANDALONE]` and rule `shareholding.every_period`
  (`required_in` quarter/half/nine-month/year, `applicability.yaml:57-63`). The `templates.yaml`
  `shareholding_category` members are vendor-shaped: `promoter_group`, `fpi`, `dii`,
  `mutual_funds` and `other_dii` under `dii`, `insurance` under `other_dii`, and `government`,
  `public`, `others` and `custodian_dr` with no parent. The `denominator` axis has
  `TOTAL_SHARES`, `VOTING_RIGHTS` and `PROMOTER_HOLDING`. `share_class` and `holder` are
  `ENTITY_EVIDENCE` axes. The loader refuses aggregation lists holding a member and its
  descendant (`canon/dictionary_validation.py:382-400`).
- **Run path (results-only).**
  - `request_for` has no family (`compare/run.py:81-112`). `RunScope.sources` must be in
    `FIRST_PARTY_SOURCES`, built from the `FirstPartySurface` enum (`run_models.py:56,137-145`),
    so extending that enum would change the default source tuple and every run identity.
  - `RUN_FAMILY`/`RUN_FRAMEWORK` are `FINANCIAL_RESULTS`/`IND_AS` (`engine.py:117-118`), used by
    the engine (`:314,457-482`) and `RunLoader` (`resolve_loader.py:170,206-225`).
  - `_group_rows` calls `fiscal_periods` (raises off quarter-end, `engine_attempts.py:43-54`) and
    `_currency` (raises unless exactly one reporting currency, `engine.py:420-450`)
    unconditionally (`engine.py:266-270`). `_context` uses `DocumentType.FINANCIAL_RESULTS`
    (`:401`), and `ApplicabilityContext` refuses an `INSTANT` period kind
    (`canon/applicability.py:83-89`).
  - `extractor_pin(representation)` hashes the results adapter files (`run_config.py:55-73,159-168`),
    and `vendor_extractor_pin` looks up `VENDOR_EXTRACTORS` by source only (`:171-183`).
    `pin_config` and `pin_versions` refuse other content under a pinned version (`:300-318`).
  - `RunStore.latest_run` filters entity, period end and basis, not family (`run_store.py:348-358`);
    `compare report` uses it unless `--run` is given (`api/compare_cli.py:146-151,370-381`).
  - `RunScope.vendors` is excluded from serialisation when empty (`run_models.py:110-127`), the
    precedent for a default-excluded field.
- **Mappings and constructions.** `MappingEntry` has static `dimension_members` and one dynamic
  member source, `XBRL_DESCRIPTION`, which fills only the segment axis
  (`evidence/interpret.py:650-668`). A `ConstructionRule` has no output dimensions
  (`mapping_models.py:198-235`): `construct` copies the first operand's key (`interpret.py:338-345`),
  selector operands are built without members (`capture_interpretation.py:367-384`), and the
  loader refuses selector constructions that target a dimensioned row (`mapping.py:419-430`).
  A selector operand reading reuses the direct interpretation's id
  (`capture_interpretation.py:355-357`), so the stored direct row stays `UNMAPPED`.
- **Identity.** `verify_xbrl_identity` checks context entities and identity facts but also needs
  a results scope and nature declaration (`member_identity.py:115-140`). `issuer_values(conn,
  entity_id, as_of)` gives the one security's ISIN, NSE symbol and BSE scrip held at a date
  (`entity/identity_layers.py:145-160`).
- **Parsers.** `ingest/screener_shareholding.py` (631 lines) and `ingest/tijori_shareholding*.py`
  read Screener's and Tijori's shareholding tables; Tijori's was built on an unretained
  2026-08-25 capture, so only synthetic fixtures exist. Upstox has only the route
  `/v2/fundamentals/{isin}/share-holdings` (`ingest/upstox_source.py:347-350`) and documentation
  (`docs/research/upstox-api-schemas/fundamentals.md:136-170`: five categories, never-null values,
  no documented precision). `upstox_statements.py` parses statements only; no share-holdings
  reader exists.
- **Acquisition.** D6's generation format is `discovery-manifest.json` plus `NN.bin` files
  (`Request`, `acquiring_fetch`, `write_generation`, `replay_fetch`, `store_captures`). It
  requires exactly one NSE master entry to fix `as_of`. `store_captures` assumes success (empty
  body fallback, HTTP 200, `OK`, `COMPLETE`, `discovery.py:641-690`); D6 passes it only
  successful captures. `ingest_vendor` turns a body-less outcome record into its attempt
  (`vendor_ingest.py:132-145`). `live_transport` sends Upstox's bearer only on
  `UPSTOX_STATEMENT` (`api/onboard_cli.py:248-282`); the instrument master is on
  `assets.upstox.com` (`discovery.py:137`).
- **Retained data (checked with `ls` on 2026-10-17).** No NSE shareholding filing, no Tijori
  shareholding page and no Upstox share-holdings response is retained. `data/raw/watchlist/<sym>/`
  holds results XBRL, PDFs and listings. The retained Screener pages contain the Shareholding
  Pattern (`#shareholding`, with `quarterly-shp`/`yearly-shp` tabs whose ids appear twice); Apar's
  quarterly table has Promoters/FIIs/DIIs/Public and an "Aug 2026" column, and Government
  appears only in its yearly table. **Live acquisition is required for every source.**
- **Credentials.** `scripts/credentials.sh` exports `SCREENER_SESSION_COOKIE`,
  `TIJORI_SESSION_COOKIE` and `UPSTOX_ANALYTICS_TOKEN`, and it refreshes stale sessions. NSE needs
  no credential. The 2026-10-17 live smoke reached all three vendors.
- **Shared tests.** `test_frozen_manifests.py` locator shapes include `xbrl`, `screener` (one
  `data-table` per element id) and `field`; the `upstox` shape reads statement blocks only. The
  existing `check_stage3` is the *ledger* Stage 3 check, and `-k stage3` also selects
  `ledger_stage3` ids (harmless, since both must pass). `stage1_e2e_support.expected` projects
  rows using header `pins` (basis, framework), `units` and `row_units` (`:317-345`).
  `manifest_support.py` is 647 lines. `scripts/verify_project.sh:61` already names the D8 exit
  test.
- **Open beads.** `eqos-g2q` and `eqos-ghv` do not touch D8. Shareholding attaches to entities
  already seeded, with no onboarding, and the family fixture uses only Apar's Q1 FY27 XBRL.

## Rulings (proposed; Sol approves with the plan)

- **R1 Paths and versions.**
  - The roadmap's `config/dictionary/v1/` becomes a new complete `config/dictionary/v3/`: v2
    plus additions only. Every v2 file is byte-identical in v3 except `templates.yaml` (members
    appended) and `applicability.yaml` (one period kind appended, R4), and `derived.yaml` (new
    rows appended, R5). No v2 row, member or parent changes.
  - Mappings: `config/mappings/shareholding_filing/v1/shp.yaml` (first-party),
    `screener/v3/shareholding.yaml`, `tijori/v4/shareholding.yaml`, `upstox/v3/shareholding.yaml`
    and `upstox/v3/constructions.yaml`, and set `config/mappings/v6.yaml` (v5 plus these).
  - All of these, and the four extractor version names, are fixed in Task 3 and never edited
    after their first commit (Constraints).
  - Code: the origin table and acquisition in `ingest/shareholding_filing.py` (the roadmap path);
    the SHP adapter in `evidence/shareholding_filing.py` (hashed by `nse-shp-v1`, so it holds
    extraction only); package ingest in `evidence/shareholding_ingest.py`; vendor extractors in
    `evidence/vendor_shareholding.py`; the family table in `compare/run_family.py`; CLI and
    ingest orchestration in `api/shareholding_cli.py`. Generations go under
    `data/raw/shareholding/<SYM>/gen-<n>/`. The results ingest (`first_party_ingest.py`) and
    `FirstPartySurface` are not generalised.
  - No migration, because the schema already admits `SHAREHOLDING` packages, framework `UNKNOWN`,
    `occurrences.disclosure jsonb` and JSON/HTML representations (migrations 0001, 0006).
  - Stage D8.2 spans Tasks 2–4 and D8.3 spans Tasks 3, 5 and 6. The orchestrator edits the
    roadmap row.
- **R2 Source (inference, settled by the probe).** The source is the NSE listing at `GET
  https://www.nseindia.com/api/corporate-share-holdings-master?index=equities&symbol=<SYM>`
  (surface `("nse","SHAREHOLDING_LISTING")`, JSON, `IDENTITY`). Each listing row links an XBRL
  instance on `nsearchives.nseindia.com` (`("nse-shareholding-xbrl","NSE_SHP_XBRL")`, XBRL,
  `FIRST_PARTY`).
  - Nothing retained shows the endpoint, its fields or the SHP taxonomy. They come from
    `docs/research/libs-pipeline-capability.md:148-149` and from general knowledge.
  - Task 2's probe runs after registration (Task 1), captures under that authority, and retains
    its generations as the phase's evidence.
  - If the probe contradicts R2–R5, the orchestrator amends them in the probe record, and Sol
    rules on the amendment before Task 3 is dispatched.
- **R3 Extraction status is `NOT_APPLICABLE`.**
  - The issuer files one representation, the XBRL. NSE's listing summary and any NSE rendering are
    derived by the exchange from that instance. They are metadata for identity and knowledge
    time, never an extraction pair. Extraction table row 1 therefore applies.
  - The manifest records the representations each retained submission holds.
  - If the probe finds a second issuer-filed representation, the orchestrator stops and re-plans.
- **R4 Measurement semantics.**
  - **Instant.** The instant is the filing's shareholding date (the XBRL context instant). It
    must equal the listing row's date, otherwise `PARSE_FAILED`. A non-quarter-end filing is its
    own instant, and the shareholding run path never calls `fiscal_periods` (R6). Knowledge time
    is the listing's broadcast time (Asia/Kolkata).
  - **Basis and framework (run boundary).** The filing declares neither. A `SHAREHOLDING` package
    is stored `STANDALONE` with framework `UNKNOWN`, and a shareholding run scope must be bases
    `(STANDALONE,)`, otherwise refused. Dictionary rows keep `[CONSOLIDATED, STANDALONE]`
    unchanged. All sources share this pair, so it never discriminates between them.
  - **Applicability.** v3 appends `INSTANT` to `shareholding.every_period.required_in`.
    `ApplicabilityContext` accepts `INSTANT` only with `DocumentType.SHAREHOLDING_PATTERN`. No
    context decidable before changes its decision, because `INSTANT` was refused before.
  - **Hierarchy.** v3 appends SEBI-format members with complete parents, and reuses no v2
    member:
    - `sebi_promoter_group` (A)
    - `public_shareholding` (B), with `institutions_domestic` (B1), `institutions_foreign` (B2),
      `central_state_government` (B3) and `non_institutions` (B4) under it
    - `non_promoter_non_public` (C), with `custodian_dr_holders` (C1) and
      `employee_benefit_trust` (C2) under it
    Names are final in Task 3 from the probe's table labels. The v2 members stay declared and
    unused by v6. Subcategories are not added (Out of scope).
  - **Denominator.** Each first-party percentage takes the denominator its element or format
    heading states, cited in the probe record. A vendor percentage takes `TOTAL_SHARES` or
    `VOTING_RIGHTS` only when a retained structure or definition states it (Upstox's
    documentation, a vendor column heading). Where nothing retained distinguishes the two, the
    label is refused (`UNMAPPED`); equal numbers never decide it.
  - **Share class.** New `MemberSource.SECURITY_ISIN` fills the `share_class` axis from the
    occurrence's `native_context["security_isin"]`. The first-party adapter sets it from the
    filing's ISIN after the identity gate. Vendor extractors get it from the API layer, which
    resolves `issuer_values` at the instant and records the identity slice in the context.
    With no single security, or no resolution, nothing is set: the occurrence is keyless and
    never pairs. The member is the ISIN, a public identifier, so it is portable across
    databases.
  - **Identity gate (SHP).** Every context entity identifier (NSE, SEBI and BSE schemes) and every
    ISIN, symbol and scrip identity fact must equal the issuer identifiers held at the instant
    (`issuer_values`); otherwise the submission is `IDENTITY_REJECTED` and nothing is written. The
    adapter imports `IssuerIdentifiers`, the scheme constants and `ACCEPTED_ENTITY_IDS_BY_ISIN`
    but does not call `verify_xbrl_identity`, which requires a results scope.
  - **Completeness.** Each occurrence's `disclosure` carries `format_version` (the taxonomy
    identity) and `completeness`. Category totals are `COMPLETE`. Holder lists are `THRESHOLDED`
    with `threshold_pct` and its denominator, as located by the probe. A threshold the filing
    does not state is not invented: the list is recorded `THRESHOLDED` with the probe's cited
    regulatory threshold, or the probe escalates. Holder occurrences have no mapping, so they are
    `UNMAPPED` and keyless. An absent holder therefore has no occurrence, key or value.
  - **Vendor month labels.** A label maps to the month-end instant only for Mar, Jun, Sep and Dec.
    Other months are `PERIOD_AMBIGUOUS`: they are kept but not comparable.
- **R5 Pairing (semantics from retained evidence).**
  - **Rule.** Every mapping's denominator and member set rests on retained structural or
    definitional evidence cited in the probe record: an XBRL element or context, a format
    heading, a vendor table's complete row set, or a vendor field definition. Arithmetic over the
    three filings is a consistency check only. A mismatch refutes a ruling, and a match never
    establishes one. A label with more than one surviving alternative is refused (`UNMAPPED`),
    never guessed. Examples: FPI only versus all of B2; B4 versus B4 + C when C is zero; total
    shares versus voting rights.
  - **Denominators.** The denominator is a key dimension, so different denominators are
    different keys and never pair. No new code is needed.
  - **Public.** Each vendor residual label (Screener "Public", Upstox `retail_and_other`, Tijori's
    equivalent) maps to the aggregate its evidence fixes:
    - one filed member, B included, maps directly to it;
    - a sum maps to a v3 derived row per distinct basket, a `DECLARED` dimensional aggregation of
      `shp_holding_pct` over that member list into an output member named for the list. The
      vendor value is published, and the first-party side is computed, as in the Screener
      "Expenses" precedent. Different baskets are different canonical ids and never pair;
    - an unresolved label stays `UNMAPPED`.
    "Retail" is never equated with Public by name.
  - **DII.**
    - A published DII maps to `institutions_domestic` only if its evidence fixes it as B1.
    - A vendor listing only subcategories (Upstox `mutual_funds` and `other_dii`) gets one
      source-scoped selector construction into B1, if the probe evidences that their sum is B1.
      `ConstructionRule` gains optional output `dimension_members` and `member_source`
      (excluded from serialisation when empty). `_operand_entry` gives each selector operand the
      rule's output members, so the operands group at the output key and `construct` keeps it.
      The loader accepts a dimensioned target only with output members that fit its template.
      There is no new operator.
    - The subcategory lines stay `UNMAPPED`, so no key carries a subcategory member.
  - **FII.** An FII label maps to `institutions_foreign` only when its evidence fixes B2;
    otherwise it is refused.
  - **Tiers.** Every vendor mapping is `EQUIVALENCE_UNPROVEN`, so outcomes are at best
    `AGREE_UNQUALIFIED` or `ANOMALY` and never trusted. Precision comes from displayed decimals
    for Screener and Tijori and from `decimals` for XBRL. Upstox pairs are diagnostic and
    `PRECISION_UNSUPPORTED`, and no precision is invented.
- **R6 Run.**
  - `compare/run_family.py` maps each `FilingFamily` to its framework, document type, first-party
    sources and XBRL extractor pin. `FINANCIAL_RESULTS` keeps exactly today's
    `FIRST_PARTY_SOURCES` tuple, `IND_AS`, results document type and results pins.
    `SHAREHOLDING` takes `("NSE_SHP_XBRL",)`, `UNKNOWN`, `SHAREHOLDING_PATTERN` and `nse-shp-v1`.
  - `RunScope.family: FilingFamily = FINANCIAL_RESULTS` is excluded from serialisation at its
    default, so existing identities and replays are unchanged. Source validation becomes
    per family, and shareholding requires bases `(STANDALONE,)`.
  - `request_for(..., family=)` defaults its sources and pins from the table. `load_run_config`
    and replay pick `extractor_xbrl` by family, so ingest, comparison and replay hash the same
    SHP sources. `RunLoader` and the engine read family and framework from the scope.
  - For `SHAREHOLDING`, `_group_rows` skips `fiscal_periods` and `_currency` (shareholding rows
    are non-monetary), and `_context` uses `SHAREHOLDING_PATTERN` with `INSTANT`. The results
    path is unchanged, and `COMPARISON_SEMANTICS` is unchanged, which the Stage 1, 2 and 4 e2es
    prove.
  - `engine.py` stays ≤ 800 lines by moving a pure helper (e.g. `_currency`) into
    `engine_context.py`.
  - The CLI gets `compare run --family {financial_results,shareholding}` and the same option on
    `compare report`. `latest_run` filters on the family: an absent family means financial
    results.
- **R7 Companies: APARINDS, ETERNAL and TITAN at 2026-06-30.**
  - All three are development companies in `config/watchlist.yaml` (Tijori ids 4290, 43813
    and 81) with full vendor coverage in the live smoke.
  - They may discriminate residual baskets (inference until the filings are read): ETERNAL has no
    promoter group and a single-holder "Others" bucket, and TITAN has a government bucket
    (`ingest/screener_shareholding.py` docstring; vendor values private,
    `data/raw/shareholding/d8-doc-private/d8-doc-inline.md`
    inline-5, SHA-256 `f18a2b2a7c46e0b1e6c5bea40e8fc75bd03375e17630842397628da8223a229b`).
  - Apar's Q1 FY27 results XBRL shares the 2026-06-30 end date (the family fixture).
  - Not chosen: POLYCAB, THERMAX and CGPOWER (no known discriminating feature).
- **R8 Acquisition and ingest.**
  - One live acquisition, the probe (Task 2), writes one generation per company in D6's format:
    the NSE master (fixes `as_of`, supplies the ISIN), the listing, every SHP submission dated
    at the instant (revisions included), the Screener company page, the Tijori shareholding
    page, and Upstox share-holdings by ISIN.
  - Authorisation is `surface_authority` plus the origin table in `ingest/shareholding_filing.py`.
    `live_transport` sends the Upstox bearer only for `UPSTOX_ROUTED` surfaces on
    `https://api.upstox.com`, never to the instrument master.
  - `acquire(symbol, instant, fetch)` (Task 4) derives the same request sequence from the master
    and listing. `fundamentals shareholding acquire` builds `acquiring_fetch(live_transport(), …)`
    in the API layer for later operator runs, never scheduled.
  - `fundamentals shareholding ingest --symbol --raw-root --snapshot-root [--generation]` replays a
    generation and orchestrates in `api/shareholding_cli.py`:
    - successful captures go to `store_captures`, whose Upstox route condition widens in place
      to `UPSTOX_ROUTED`;
    - each failed vendor request is written as a body-less outcome record and passed to
      `ingest_vendor`, so its failure is an attempt;
    - the first-party part goes to `shareholding_ingest`;
    - vendor captures go to `ingest_vendor` with the new extractors.
  - A non-OK listing or SHP response makes the generation unusable for first-party ingest. The
    command refuses it without writing, and the operator acquires a new generation.
  - D8 lands before D9, so it records only catalog retention authority (ledger §6 item 7).
- **R9 Manifest independence (D6 discipline, scaled).**
  - **Kept:**
    - The author is a fresh Opus worker. It uses a `scratchpad/` aid that never imports
      `fundamentals`, and reads only the pinned generation bytes, spec §1/§4/§5/§7, R2–R7 and the
      probe record's shape section. It never runs D8 code, reads run output, or opens the D8
      config or the probe record's ruling section, so it decides each aggregate independently.
    - Every value has a locator into hashed bytes.
    - Sol gives a payload-bound approval, which is committed before the e2e's first commit (the
      existing order test).
    - A later disagreement is settled by evidence: either a code fix under a new version, or a
      newly approved payload committed before the e2e change.
  - **Dropped:** the freeze descriptor, burns and the held-out draw. D8 makes no claim about
    unseen companies.
