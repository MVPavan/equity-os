# D8 Shareholding Filing Source Implementation Plan

Status: draft, awaiting the Sol plan review.

**Origin:** the Phase D8 row of [`roadmap.md`](../roadmap.md) (stages D8.1–D8.5, the exit, the edge
D8 → D1b, and "Not edges"); stages `eqos-17r.1`–`.5` (acceptance read from bd on 2026-10-17). Specs:
[data spec](../../../specs/2026-10-11-canonical-financial-data-and-cross-source-comparison.md) §7,
§3 (source authority), §4 (key, disclosure metadata), §5 (shareholding roles and tables), Success
Criteria Stage 3, and the 2026-10-14 Family fixture amendment (a retained adapter→run
family-isolation fixture is required in Stage 3); [ledger spec](../../../specs/2026-10-12-report-ledger-memory-and-data-lifecycle.md)
§6 item 7. Conventions follow [D6](D6.md) and [D7](D7.md).
**Goal:** the exchange shareholding filing is a registered first-party source. Apar, ETERNAL and
TITAN are captured with explicit instant, category, denominator, share class and completeness,
and their promoter, public and institution aggregates are compared with the real Screener,
Tijori and Upstox (diagnostic) captures, matching a frozen Stage 3 manifest.
**Out of scope:**
- Admitting shareholding facts to the fact store.
- Comparing holders or pledges. No vendor holder or pledge surface is mapped.
- Screener investor drill-downs.
- Measuring Upstox independence. Upstox stays diagnostic.
- Any `EQUIVALENCE_DEMONSTRATED` shareholding mapping. Three companies are fewer than D3's five.
- BSE shareholding filings.
- Retention classes. D9.2 classifies these captures.
- Scheduled or market-wide capture.
- Removing the vendor-shaped v1 category members, which would be a major version.
**Constraints:**
- Migrations are forward-only. `0001`–`0026` are immutable, and D8 plans none (R1). If one is
  forced, it is `0027_shareholding.sql`.
- Source authority is checked before capture and before interpretation. An unregistered surface
  gives `NOT_AUTHORISED` and is never sent.
- Absence is never a value. Nothing is zero-filled, and an absent holder is unknown.
- Models never compute numbers. Manifest values come from a `scratchpad/` aid that never imports
  `fundamentals`.
- The hashed sources of `screener-v1`, `tijori-v4` and `upstox-v2` do not change (`run_config.py:80-120`;
  the Stage 1 manifest pins them).
- `entity/discovery.py` (800 lines) gets in-place edits only, net 0 lines. `compare/engine.py`
  (795) stays ≤ 800. `test_frozen_manifests.py` (783, plus up to 5 from D7.5) grows ≤ 10 lines.
- Tests make no network request (socket guard on replay). Credentials are read only through
  `scripts/credentials.sh` at run time and are never printed or written.
- Held-out discipline applies. Only development companies are used, and the paths in Constraints
  of D6/D7 are never opened.
- Code uses strict mypy, ruff, frozen Pydantic models, enums and structlog. Every module traces
  to a stage acceptance.

## Grounding (current state)

- **Catalog.** `BUILTIN_SOURCES` has no shareholding source. `VENDOR_SURFACES` registers role and
  retention authority per `(source, surface)` (`contracts/source_catalog.py:177-274`).
  `surface_authority` raises `SurfaceNotAuthorisedError`. In response, `ingest_vendor` stores a
  `NOT_AUTHORISED` attempt (`evidence/vendor_ingest.py:126-136`), and `acquiring_fetch` logs
  `NOT_AUTHORISED` without sending (`entity/discovery.py:317-337`).
- **Dictionary.** Each version is a complete directory, and v2 is the current one (Stage 1 pins v2
  and mapping set v4; set v5 is the latest). The v2 `shareholding.yaml` declares four rows:
  `shp_holding_pct`, `shp_promoter_pledged_pct`, `shp_num_shareholders` and `shp_holder_pct`.
  The `templates.yaml` `shareholding_category` members are vendor-shaped: `promoter_group`,
  `fpi`, `dii`, `mutual_funds`/`other_dii` under `dii`, `insurance` under `other_dii`,
  `government`, `public`, `others` and `custodian_dr`. The `denominator` axis has
  `TOTAL_SHARES`, `VOTING_RIGHTS` and `PROMOTER_HOLDING`, and `share_class` takes its members
  from entity evidence. Rule `shareholding.every_period` is a placeholder keyed to period kinds.
- **Engine and schema.** The engine is results-only. `RUN_FAMILY` is `FINANCIAL_RESULTS`,
  `RUN_FRAMEWORK` is `IND_AS`, and shareholding rows are excluded (`compare/engine.py:117-119,260-264`).
  Keys come from evidenced member sets (`:295-367`). Dimensional aggregation already exists in
  formulas (`DECLARED`/`ENTITY_EVIDENCE`, e.g. `segment_revenue_members_total`).
  `RunScope.vendors` is excluded from serialisation when it is empty (`run_models.py:112-127`).
  Migration 0001 already admits `SHAREHOLDING` packages, framework `UNKNOWN` and
  `occurrences.disclosure jsonb`, and 0006 admits HTML/JSON representations.
- **Mappings.** `MappingEntry.dimension_members` exists. A `ConstructionRule` sums operands from
  one capture but has no output dimension (`evidence/mapping_models.py:150-230`).
  `VENDOR_EXTRACTORS` is keyed by source (`compare/run_config.py:80-120`).
- **Parsers to reuse, without editing.** `screener_company_discovery.shareholding_table` and
  `ingest/screener_shareholding.py` read the Shareholding Pattern tables. `ingest/tijori_shareholding*.py`
  reads Tijori's typed table and checks identity by `<h1 comp_id>` against `tijori_company_id`;

  exist. `ingest/upstox_source.py:350` has the route `/v2/fundamentals/{isin}/share-holdings`,
  which has five categories (`promoters`, `fii`, `mutual_funds`, `other_dii`,
  `retail_and_other`), never-null values and no documented precision
  (`docs/research/upstox-api-schemas/fundamentals.md:136-170`).
- **Acquisition.** D6's generation format is `discovery-manifest.json` plus `NN.bin` files
  (`Request`, `acquiring_fetch`, `write_generation`, `replay_fetch`, `store_captures`). It

  `onboard_cli.live_transport` sends Upstox's bearer only on `UPSTOX_STATEMENT` (`:247-280`).
- **Retained data (checked with `ls` on 2026-10-17).** No NSE shareholding filing, no Tijori
  shareholding page and no Upstox share-holdings response is retained. `data/raw/watchlist/<sym>/`
  holds results XBRL, PDFs and listings. `data/raw/snapshots/v1/` holds Tijori financials and

  - The roadmap's `config/dictionary/v1/` becomes a new complete `config/dictionary/v3/`: v2
    plus additive shareholding changes. Published versions are immutable, and v2 set the
    precedent.
  - Because the first-party mapping (roadmap D8.2) needs the category members, Task 2 creates v3
    with the first-party hierarchy. Task 4 adds the vendor-residual row. v3 is unpublished
    until exit.
  - Mappings: `config/mappings/shareholding_filing/v1/shp.yaml` (first-party, per format
    version), `screener/v3/shareholding.yaml`, `tijori/v4/shareholding.yaml`,
    `upstox/v3/shareholding.yaml` with `upstox/v3/constructions.yaml`, and set
    `config/mappings/v6.yaml` (v5 plus these).
  - Code: acquisition in `ingest/shareholding_filing.py` (the roadmap path), the first-party
    adapter in `evidence/shareholding_filing.py`, vendor adapters in
    `evidence/vendor_shareholding.py` (new modules, so no pinned extractor changes), and the CLI
    in `api/shareholding_cli.py`. Generations go under `data/raw/shareholding/<SYM>/gen-<n>/`.
  - No migration, because the schema already admits everything (Grounding).
  - Stage D8.3 spans Tasks 3–4. The orchestrator edits the roadmap row.
- **R2 Source (inference, settled by probe).** The source is the NSE listing at `GET
  https://www.nseindia.com/api/corporate-share-holdings-master?index=equities&symbol=<SYM>`
  (surface `("nse","SHAREHOLDING_LISTING")`, JSON, `IDENTITY`). Each listing row links an XBRL
  instance on `nsearchives.nseindia.com` (`("nse-shareholding-xbrl","NSE_SHP_XBRL")`, XBRL,
  `FIRST_PARTY`).
  - Nothing retained shows the endpoint, its fields (date, XBRL link, submission and broadcast
    times, record id) or the SHP taxonomy. They come from `docs/research/libs-pipeline-capability.md:148-149`
    ("NseIndiaApi `shareholding` … + SHP XBRL link"; "parse `SHP_*.xml`") and from general
    knowledge.
  - Task 2 therefore opens with an orchestrator probe. It retains one listing and one instance
    in a scratch generation and records their real shapes, the taxonomy namespace, the category
    and denominator elements and the holder-list thresholds before dispatch.
  - If the probe contradicts R2–R4, the orchestrator amends them, records the change, and Sol
    rules on it before dispatch.
- **R3 Extraction status is `NOT_APPLICABLE`.**
  - The issuer files one representation, the XBRL. NSE's listing summary (promoter and public %)
    and any NSE rendering are derived by the exchange from that same instance. They are
    metadata for identity and knowledge time, never an extraction pair. Extraction table row 1
    therefore applies.
  - The manifest records the representations each retained submission holds.
  - If the probe finds a second representation filed by the issuer, the orchestrator stops and
    re-plans. No second adapter is built speculatively.
- **R4 Measurement semantics.**
  - **Instant.** The instant is the filing's shareholding date (the XBRL context instant). It
    must equal the listing row's date, otherwise `PARSE_FAILED`. Non-quarter-end filings (Apar's
    "Aug 2026") are their own instants. Knowledge time is the listing's broadcast time (Asia/Kolkata).
  - **Basis and framework.** The filing declares neither. Shareholding keys are issuer-level:
    v3 restricts shareholding rows to `STANDALONE` (spec §3 attaches shareholding to the entity
    and share class), and the engine stamps framework `UNKNOWN` for the `SHAREHOLDING` family.
    All sources share this pair, so it never discriminates between them. This is safe because
    no shareholding row was ever evaluated (the engine excluded the family).
  - **Hierarchy.** v3 adds members for the SEBI format:
    - `public_shareholding` (B)
    - `institutions_foreign` (B2)
    - `non_institutions` (B4)
    - `non_promoter_non_public` (C) and `employee_benefit_trust` under C
    - the probe's closed list of subcategories under B1, B2 and B4
    It reuses the members whose v2 meaning fits: `promoter_group` (A), `dii` (B1),
    `mutual_funds` (under `dii`), `government` (B3) and `custodian_dr`. Existing members keep
    their declarations, and containment is added only for new members (minor version).
    `public`, `others`, `other_dii` and `insurance` stay declared and unused by v6.
    Unmapped subcategory facts remain `UNMAPPED` (LOW).
  - **Denominator.** Each first-party percentage takes the denominator its element states. A
    further denominator (e.g. diluted share capital) becomes a member only if the probe shows it
    filed. Vendor percentages are `TOTAL_SHARES` only by an evidenced mapping fact: Upstox's
    documentation, and hand arithmetic for Screener and Tijori.
  - **Share class.** The member is the equity security's internal id, resolved from the
    filing's ISIN (a mismatch gives `IDENTITY_REJECTED`). Vendor mappings assign the entity's
    single equity security. With more than one, the member is unresolved and the key is
    `NOT_COMPARABLE`.
  - **Completeness.** Each occurrence's `disclosure` carries `format_version` (the taxonomy
    identity) and `completeness`. Category totals are `COMPLETE`. Holder lists are `THRESHOLDED`
    with `threshold_pct` and its denominator: 1 % for public lists, and 0 for the promoter list,
    where every entity is listed. Both thresholds are inference until the probe confirms them.
    `shp_holder_pct` exists only at listed holders, and holder keys come only from evidenced
    members. An absent holder therefore has no key and no value, never zero. Holder keys never
    pair.
  - **Vendor month labels.** A label maps to the month-end instant only for Mar, Jun, Sep and Dec.
    Other months are `PERIOD_AMBIGUOUS`: they are kept but not comparable.
- **R5 Pairing.**
  - **Denominators.** The denominator is a key dimension, so different denominators are
    different keys and never pair. No new code is needed.
  - **Public.** Each vendor residual label (Screener "Public", Upstox `retail_and_other`, and
    Tijori's equivalent) maps only to the aggregate whose closed member list the three
    companies' filings evidence by hand arithmetic. It never maps to `public_shareholding` (B).
    "Retail" is never equated to Public.
    - If the matching aggregate is one filed member (e.g. B4), the label maps to it.
    - If it is a sum (e.g. B3 + B4 + C), v3 adds one derived row, `shp_public_residual_pct`.
      The row is a `DECLARED` dimensional aggregation of `shp_holding_pct` over that list into
      output member `public_residual`. The vendor value is published, and the first-party side
      is computed, as in the Screener "Expenses" precedent.
    - A label that matches no aggregate stays `UNMAPPED`.
  - **DII.**
    - A published DII (Screener "DIIs") maps to `dii`.
    - A vendor listing only subcategories (Upstox `mutual_funds` plus `other_dii`) gets one
      source-scoped construction that sums exactly that list into `dii`. Constructions gain an
      optional output `dimension_members`, mirroring `MappingEntry`; this is ADD only, with no
      new operator.
    - The subcategory lines stay `UNMAPPED`, so they never pair with first-party `mutual_funds`.
  - **FII.** FII labels map to `institutions_foreign` or `fpi` as the arithmetic evidences. If the
    two are equal for all three companies, the entry cites the label's definition.
  - **Tiers.** Every vendor mapping is `EQUIVALENCE_UNPROVEN`, so outcomes are at best
    `AGREE_UNQUALIFIED` or `ANOMALY` and never trusted. Precision comes from displayed decimals
    for Screener and Tijori and from `decimals` for XBRL. Upstox pairs are diagnostic and
    `PRECISION_UNSUPPORTED`, and no precision is invented.
- **R6 Run.**
  - `RunScope.family: FilingFamily = FINANCIAL_RESULTS` is excluded from serialisation at its
    default (the `vendors` precedent), so existing run identities and replays are unchanged.
  - For `SHAREHOLDING`, the engine uses the family's packages and rows, framework `UNKNOWN`,
    `period_end` as the instant, and basis `STANDALONE`.
  - The family constants and `_result_rows` move into `engine_context.py` to respect the
    800-line cap. `COMPARISON_SEMANTICS` is unchanged, which the Stage 1, 2 and 4 e2es prove.
  - The CLI gets `compare run --family shareholding`.
- **R7 Companies: APARINDS, ETERNAL and TITAN at 2026-06-30.**
  - All three are development companies in `config/watchlist.yaml` (Tijori ids 4290, 43813
    and 81) with full vendor coverage in the live smoke.
  - They give the discriminating cases for the residual (inference until the filings are read).
    ETERNAL has no promoter group and a single-holder "Others" bucket. TITAN has a
    government bucket (`ingest/screener_shareholding.py` docstring; vendor values private,
    `data/raw/shareholding/d8-doc-private/d8-doc-inline.md`
    inline-5, SHA-256 `f18a2b2a7c46e0b1e6c5bea40e8fc75bd03375e17630842397628da8223a229b`).
  - On 2026-06-30, Apar's Q1 FY27 results XBRL shares the end date (the family fixture), and
    every vendor's quarterly window covers it.
  - Not chosen: POLYCAB, THERMAX and CGPOWER (no known discriminating feature), and the companies
    not admitted.
- **R8 Acquisition and ingest.**
  - `fundamentals shareholding acquire --symbol --instant --raw-root` is operator-run and never
    scheduled. It writes one generation per company in D6's format:
    - the NSE master (fixes `as_of` and supplies the ISIN)
    - the listing
    - every SHP submission dated at the instant, so revisions are retained
    - the Screener company page
    - the Tijori shareholding page
    - Upstox share-holdings by ISIN
  - Authorisation is `surface_authority` plus an origin table in `ingest/shareholding_filing.py`.
    Transport is `live_transport`, edited in place so the Upstox bearer goes to every `upstox`
    request.
  - `fundamentals shareholding ingest --symbol --raw-root --snapshot-root [--generation]` replays
    the generation and registers captures via `store_captures`. Its Upstox route condition widens
    in place to `UPSTOX_ROUTED` (net 0 lines).
  - Ingest then writes the first-party package (family `SHAREHOLDING`) and runs `ingest_vendor`
    with the new extractors. `VENDOR_EXTRACTORS` resolves `(source, surface)` before `source`.
  - D8 lands before D9, so it records only catalog retention authority (ledger §6 item 7).
- **R9 Manifest independence (D6 discipline, scaled).**
  - **Kept:**
    - The author is a fresh Opus worker. It uses a `scratchpad/` aid that never imports
      `fundamentals`. It reads only the pinned generation bytes, spec §5/§7 and R2–R7. It never
      runs D8 code, reads run output, or opens the D8 dictionary or mapping files, so it decides

    - Every value has a locator into hashed bytes.
    - Sol gives a payload-bound approval, which is committed before the e2e's first commit (the

    - A later disagreement is settled by evidence: either a code fix, or a newly approved payload
      committed before the e2e change.
  - **Dropped:** the freeze descriptor, burns and the held-out draw. D8 makes no claim about
    unseen companies.

### Task 2: Acquisition, retention and first-party occurrences

Goal: generations for APARINDS, ETERNAL and TITAN are retained under recorded authority, and
their filings ingest with explicit instant, category, denominator, share class and completeness.
Holder lists are `THRESHOLDED` with the threshold recorded, and an absent holder is never zero.
Stage: eqos-17r.2
Files: listed in the File map (Task 2 rows).
Interfaces:
- Consumes: Task 1's surfaces; `acquiring_fetch`, `write_generation`, `replay_fetch`,
  `store_captures`, `live_transport`.
- Produces:
  - `acquire(symbol: str, instant: date, fetch: Fetch) -> list[Capture]`
  - `ingest_shareholding(symbol, generation: Path, snapshots, repository, config) -> ShareholdingIngestReport`
    (`package_id`, `attempts`, `occurrences`, `interpretations`)
  - Disclosure keys `format_version`, `completeness` (`COMPLETE`/`THRESHOLDED`),
    `threshold_pct` and `threshold_denominator`
  - CLI `fundamentals shareholding acquire --symbol S --instant D --raw-root <dir>` and
    `fundamentals shareholding ingest --symbol S --raw-root <dir> --snapshot-root <dir> [--generation N] [--config-root config]`
  - Dictionary `v3`; mapping set `v6` with the first-party entries
Approach:
- **Probe first (orchestrator, before dispatch).** Settle R2–R4 on real bytes and record the
  results in the brief.
- **Acquire.** Run live once per company. Acquisition follows R8, with the instant from R7.
  Generations are gitignored.
- **Adapter.** The adapter reads the instance with `extract/xbrl_dimensions.py`. It resolves
  the instant, the ISIN (checked against the entity's security) and the taxonomy (unknown gives
  `UNSUPPORTED_SCHEMA`). It emits every fact as an occurrence with disclosure metadata, and
  every category, denominator and holder member comes from the format.
- **Ingest.** Each submission becomes a `SHAREHOLDING` package. Knowledge time comes from the
  listing, and revisions supersede in the family. Unchanged inputs write nothing.
- **Vendor bodies.** These are only registered here; they are interpreted in Task 4.
Verification: `uv run pytest tests/fundamentals/test_shareholding_filing.py` (`pg`, `retained`,
socket guard), run via the CLI over the three generations:
- **Packages and authority.** Each company has one package at 2026-06-30 with listing knowledge
  time, and every capture ref is on a registered surface with its authority.
- **Interpretations.** `shp_holding_pct` exists at A, B, B1, B2, B3, B4 and C. Each has its
  filed denominators and the security's share-class member, and the spot values equal lexemes
  the test reads with lxml.
- **Holders.** Every holder occurrence is `THRESHOLDED` with its threshold. In a marked
  generation that withholds one public holder, that holder has no occurrence or interpretation,
  and no interpretation anywhere has a zero that was not printed.
- **Refusals.** A marked listing date that differs from the instance gives `PARSE_FAILED`, and
  a marked namespace gives `UNSUPPORTED_SCHEMA`.

## Risks

- **Inferred endpoint and taxonomy (R2).** The probe gates Task 2, and any amendment is ruled
  by Sol before dispatch.
- **False corroboration.** This is the phase's main risk. It is mitigated by three things:
  - denominators and residuals are key dimensions;
  - every vendor tier is unproven, so nothing is trusted in D8;
  - each label is evidenced by arithmetic, and the manifest decides its aggregate independently.
  State plainly at exit that no shareholding cell is trusted until five companies qualify.
- **Upstox is uninformative.** Every Upstox pair is `PRECISION_UNSUPPORTED` until a documented
  precision exists. This is spec-faithful and reported as such.
- **Engine and extractor pins.** A careless edit breaks Stage 1 replay. The e2es and pin tests
  guard it.
- **Live acquisition.** NSE throttling, Tijori page drift and session expiry (Q1). A failed
  request is re-run as a new generation, never patched.
