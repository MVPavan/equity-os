**Purpose of this document.** Factual, spec-cited source material for the Orchestrator to build the human-facing "architecture of record" artifact that gates implementation. Everything here is drawn from the 25 approved specs (`docs/specs/equity-os-s01…s25*.md`), the v2 decision register (`docs/blueprint/funda-blueprint-implementation-decision-register-v2.md`), the third-order disposition report, the component ledger (`docs/goals/equity-os-blueprint-component-ledger.jsonl`, 213 rows: 169 canonical + 44 aliases), and the human-review artifact. Terms follow `CONTEXT.md`.

**Status caveat (load-bearing).** Every spec S01–S25 is `DRAFT — AWAITING FRESH SOL XHIGH REVIEW`; none is Accepted. No register row is Accepted. Per S01 invariant 2, *"No product operation, including private/internal research, is authorized … before A-01 is `Accepted`."* Three human-review items (HR-0001/0002/0003) are `OPEN_BLOCKING` and, by their own scope text, keep *"all product implementation … blocked"* (see §10). This brief describes what the system **will** and **will not** do once built and approved, not what exists today. Where a fact is my inference rather than spec text, it is marked "(inferred)".

**Reviewer-role note.** Specs say "fresh Sol xhigh review" / gate type `DELEGATED_ARTIFACT_APPROVAL`, and a few gate cells literally name `gpt-5.6-sol`. Per the `CONTEXT.md` role-binding rule, this brief calls it the **delegated artifact reviewer** (an independent reviewer of the document) and does not treat the model name as an architecture fact.

## 1. One-paragraph purpose (S01)

Equity-OS is a **persistent, evidence-governed equity-research system for Indian markets — not an autonomous stock-picking chatbot** (`CONTEXT.md`; `.claude/project/brief.md`). Its operating doctrine: *"SQL records what happened. Curated memory preserves what was learned. Deterministic code calculates implications. Agents investigate, challenge, and explain. Execution remains separately controlled."* The user is a small internal research team (a solo builder plus an accountable analyst/product-owner role); S01 records the **initial intended posture as private/internal research** and *"records intent only"* — it names `intended_users` as "roles, not inferred audiences." The first product deliverable is a **fixed-state earnings-review workflow (S14)**: given a company's new quarterly-result package and an approved prior thesis, produce a reviewable, source-backed update showing what changed in facts, management commitments, calculations, uncertainties, and thesis. S01 itself only owns the boundary/name/distribution-gate records (register A-01, A-09, E-08); it *"does not itself approve any boundary, name, legal conclusion, regulatory conclusion, or distribution mode."*

## 2. Boundaries & non-goals

### 2.1 S01 identity / operating / distribution boundary

S01 defines four closed, versioned, content-hashed records: `OperatingBoundary`, `ProductIdentityDecision`, `BoundaryChangeRequest`, `DistributionBoundaryGate`. The `OperatingBoundary` must separately address six dimensions: **private/internal use, public distribution, paid distribution, personalized output, execution linkage, and the intended future boundary**. Every non-private mode `Defaults to PROHIBITED`. Key invariants (quoted):

- Inv. 1: *"`legal_sufficiency_claimed` is always `false`; a boundary document that claims sufficiency is invalid."*
- Inv. 3: *"Missing, stale, ambiguous, or conflicting mode data resolves to the more restrictive boundary."*
- Inv. 4: *"`PROPOSED` is not authorization. Only `APPROVED` plus current typed human records may open a mode after A-01 is `Accepted`."*
- Inv. 5: *"Public, paid, personalized, and execution-connected behavior is disabled while E-08 remains `Deferred`."*
- Inv. 7: *"Execution linkage additionally remains blocked by S04/E-09 even if E-08 is later activated and accepted."*
- Inv. 8: the working label `Equity-OS` *"is never product-name approval"*; the blueprint name "Funda" is unverified (A-09 open).

**S01 explicit "will NOT" (non-goals, quoted):** *"No claim of legal sufficiency or regulatory compliance. No legal, trademark, or regulatory advice generated by an agent. No public, paid, personalized, or execution-connected release. No execution trust-domain design; S04 owns E-09. No provider/data-rights decision; S02 owns A-05 and C-13."* Crossing the boundary to any paid/public/personalized/execution mode is gated on E-08 (`Deferred`), which requires a legal register transition plus distinct `LEGAL_REVIEW`, `REGULATORY_REVIEW`, and `DISTRIBUTION_APPROVAL` human resolutions.

### 2.2 S04 execution trust domain (what runs where, what is trusted)

S04 is **dormant-only** (register E-09, `Deferred`). It defines the fail-closed boundary that *"must exist before any Equity-OS output can reach an execution system"* and *"does not enable paper or live trading, and it does not permit research agents to invoke execution."* Trust model:

- **Research runtime (the only domain that runs in the first release):** may produce an **inert `ExecutionIntent` candidate only** — *"The candidate cannot be submitted directly and has no credential-bearing or executable field."* It has no execution credentials, no execution-DB write authority, no submission endpoint.
- **Execution domain (future, separate service):** when activated it MUST be *"a separately deployed service boundary with no in-process execution path from the research runtime"*, with execution-only credentials, an execution-owned store, deterministic versioned pre-trade limits, human approvals bound to an immutable request, a fail-closed kill switch (defaults `BLOCKED` on startup/uncertainty), and reconciliation.
- **Untrusted-input rule (recurs across S04, S07, S09, S10, S15, S16, S19):** *"No untrusted document, retrieved text, model output, claim, memory draft, or research artifact can invoke execution or obtain execution secrets."* Source content is **data, never control text** — it cannot change tools, permissions, cutoffs, promotion rules, credentials, or execution.
- **Infrastructure caveat (disposition 6.7, echoed in S03/S04/S20):** references to *"an existing Temporal, Partner, Bodha, homelab, or PostgreSQL deployment are unsupported by the reviewed files and must not be treated as architecture facts."* No such infrastructure is selected.

### 2.3 Program-wide non-goals (register §G, "Explicitly deferred from the first release")

*Full automated company initiation; GBrain as a mandatory dependency; generalized autonomous planning; multi-agent investment committee; full-universe daily research; broad sector-pack library; licensed consensus estimates unless essential; portfolio construction; historical LLM alpha claims; paper trading; live execution; local-model optimization without an Equity-OS-specific benchmark; migration to a distributed workflow engine or PostgreSQL before observed need.* These map to DEF-01…13 (see §9).

## 3. Component inventory

Every runtime subsystem the specs define, grouped by role. Format: **Name (spec · register rows · disposition)** — responsibility; inputs→outputs; stores owned; key invariant (quoted); notes. "Active" = all owned rows REQUIRED_NOW; "Mixed" = some active, some deferred; "Dormant-only" = all owned rows CONDITIONAL_UNACTIVATED.

### A. Boundary & governance

**Product/operating/distribution boundary (S01 · A-01, A-09, E-08 · Mixed).** Owns the initial boundary, product-name decision, and the fail-closed gate for any later paid/public/personalized/execution use. In: proposed posture, name-search evidence, legal/regulatory evidence. Out: versioned `OperatingBoundary`, `ProductIdentityDecision`, `DistributionBoundaryGate` result (`BLOCKED` unless all evidence current). Stores: versioned, content-hashed decision records. Invariant: *"result is derived, never trusted, and is `BLOCKED` unless all three references are present, current, content-valid, and mutually consistent."* E-08 is deferred/dormant.

**Execution trust-domain boundary (S04 · E-09 · Dormant-only).** See §2.2. Records (when activated): `ExecutionIntent`, `ExecutionControlApprovalSet`, `ExecutionRequest`, `ExecutionAuthorization`, `AuthorizationConsumption`, `ExecutionOutcome`, `KillSwitchState`, `KillSwitchResetAuthorization`. Invariant: *"Deterministic limits can narrow or reject an approved intent; no model, narrative, or operator bypass can broaden it."* Not built in first release.

### B. Sources, rights & ingestion

**Source rights, providers & consensus policy (S02 · A-05, C-13 · Active).** Owns the data-rights register scoped to the S01 boundary and the consensus-estimate decision. In: per-source terms/evidence + independently derived `SourceUsageInventory`. Out: `ProviderRightsRegister` (one `SourceRightsRecord` per source), `ConsensusDataDecision`. Ten independent rights dimensions: access, automation, caching, retention, commercial use, derived outputs, redistribution, account limits, point-in-time availability, replacement path. Invariants: *"Register completeness is exact set equality: `U == R`"*; *"Missing or ambiguous rights resolve to `UNKNOWN`, which denies the operation"*; *"Consensus data is excluded unless … `INCLUDED_LICENSED_AND_NECESSARY` is freshly derived."* No agent purchases, contacts providers, or obtains credentials.

**External-tool due diligence (S03 · E-06 OpenBB, E-07 FinanceHarness/Vibe-Trading · Dormant-only).** Dormant evaluation gates only. *"No repository lookup, web research, cloning, installation, execution, network access, or provider contact in this draft."* Records: `ExternalToolDueDiligenceRecord`, `ExternalToolAdoptionDecision` (due diligence ≠ adoption). Invariant: *"External-tool outputs never become authoritative facts merely because a tool produced them."* OpenBB, if ever adopted, *"must run out of process behind an Equity-OS-owned adapter … Core domain objects must not expose OpenBB-specific types."*

**Filing ingestion, immutable documents, point-in-time capture, conditional audio (S09 · A-06, B-09, C-02 active; C-14 audio Deferred · Mixed).** Owns the XBRL-vs-PDF coverage spike, immutable document registry, and daily/event point-in-time capture. In: approved sources (via S02), discovery-company source packages (S05). Out: `FilingCoverageObservation` matrix, `SourceDocument` (immutable bytes), `ParseAttempt` (append-only, versioned), `CaptureEvent`. Capture kinds: `MEMBERSHIP_SECURITY_CHANGE`, `PRICE`, `ANNOUNCEMENT`, `CORPORATE_ACTION`, `SHAREHOLDING_CHANGE`. Stores: immutable object store + append-only SQL. Invariants: *"Original bytes are immutable and content-addressed. Same URL plus changed bytes creates a new document occurrence; hash mismatch never overwrites"*; *"`first_seen_at` is acquisition evidence … cannot be backdated to simulate point-in-time history"*; *"Source content is data, never instructions."* Non-goal: *"Point-in-time capture prevents future loss; it is not a claim to have recreated unavailable historical data."* Parse/re-extract require a current `TransformationAuthorization`; a parser upgrade appends a new `ParseAttempt`, never overwrites.

### C. Data & evidence stores

**Source-of-truth matrix, evidence packages, retention (S10 · B-03, C-11 · Active).** Owns the authority table (which store is authoritative per record class), the frozen evidence-package contract, and retention/deletion. Out: `EvidencePackageManifest` (immutable, versioned `v(N+1)` on any input change) carrying an `S12LineageClosure`; `StorageScaleDecision`. Canonical byte profile `eos-manifest-json-v1` (shared with S11/S12). Invariants: *"No two stores may both accept canonical writes for the same field or lifecycle transition"* (anti-split-brain); *"Raw model scratchpad or hidden reasoning | None; prohibited as a product dependency"* (C-11); *"Deletion never masquerades as correction; correction never destroys prior history."* Deletion is a distinct typed human gate; *"The system must not claim reproducibility after required bytes are removed."* SQLite is the allowed Phase-0.5 default (see §9 SCALE-SQLITE).

**Run manifest, knowledge cutoff, layered reproducibility (S11 · C-09, C-15, C-16 · Active).** Owns run/attempt registration before any evidence access, one immutable UTC `knowledge_cutoff` propagated to every store and tool, and layered replay. Out: `RunManifest` + `AttemptManifest` (immutable, hash-chained versions). Cutoff contract: *"`knowledge_cutoff` means the latest knowledge time a run may observe … Every SQL query includes `knowledge_time <= :cutoff`."* Tool gateway declares each call `CUTOFF_NATIVE`, `ARCHIVED_SOURCE_ONLY`, or `NOT_CUTOFF_CAPABLE` (last is denied for historical replay and authoritative retrieval). Three reproducibility guarantees: exact-class operators replay exactly; floating-point/optimization within declared tolerances; stochastic store seed + distribution checks; evidence package reconstructs exactly; *"approved narrative bytes are immutable and content-hashed … regenerated prose is a new artifact requiring review, not proof of reproduction."* Invariant: *"Model-weight leakage is never represented as controllable store/tool leakage prevention"* (owned by S25).

**Observation/fact identity, revision, schema evolution (S12 · B-05, B-10, B-11, C-03 · Active; schema provisional).** Owns the seven-layer identity model and append-only revision/correction semantics. Layers: `SourceOccurrence` → `ExtractionResult` → `Observation` → `MeasurementKey` → `RevisionFamily`/`ReconciliationDecision` → `FactRevision` → `CanonicalSelection`. `measurement_key = entity + metric definition/version + period + statement/consolidation scope + dimension set + accounting/adjustment basis`. Revision reasons: `ISSUER_RESTATEMENT`, `SOURCE_CORRECTION`, `PARSER_RE_EXTRACTION`, `MANUAL_CORRECTION`, `NORMALIZATION_POLICY_CHANGE`. Invariants: *"'Newest' is not a valid selection policy"*; *"The system must not derive identity solely from display label, numeric value, document order, filing date, ISIN, or the latest ingestion timestamp."* Final minimum schema is **derived from vertical-slice evidence, not guessed** — B-05 and B-10 have mandatory amendment gates.

**Claim schema, vocabulary registries, evidence validation (S13 · B-06, B-12, C-04 · Active; schema provisional).** Owns `TypedClaim`, the versioned `MetricDefinitionVersion`/`PredicateDefinitionVersion` registries, and materiality/epistemic-aware validation. `TypedClaim` fields: subject, predicate_ref, object, scope, horizon, `epistemic_class` (observed/computed/inferred/forecast/opinion), confidence (separate from class), materiality_result + policy version, status, evidence_links, assumption_refs, uncertainty, supersedes, contradiction_refs. Invariant: *"Material `observed` claims require direct exact-source support. Material `computed` claims require a registered calculation trace. Missing support is `FAIL`, not a warning."* Material inferred/forecast need linked evidence + explicit assumptions + explicit uncertainty + correct labeling + visible reasoning. B-06 mandatory amendment gate; provisional until derived from real use.

**Entity/security master, relationships, corporate actions (S17 · C-06, C-07, C-17 · Active).** Owns stable opaque internal `company_id`/`security_id`/`person_id`, versioned external-identifier mappings, bitemporal factual relationships, and versioned corporate-action events. Identifier types: ISIN, EXCHANGE_SYMBOL, CIN, LEI. Relationship predicates: PARENT_OF, SUBSIDIARY_OF, MANAGEMENT_ROLE_AT, OWNS, CROSS_HOLDING_WITH. Corporate-action types: SPLIT, BONUS, RIGHTS, DEMERGER, DIVIDEND, TICKER_CHANGE, DELISTING (`event_status`: ANNOUNCED/CONFIRMED/EFFECTIVE/CANCELLED). Invariant: *"Internal IDs are stable, opaque, never reused, and unaffected by name, symbol, listing, ISIN, CIN, or LEI changes"*; *"ISIN is an external identifier … not the authority for Equity-OS object identity."* Bitemporal: valid time and knowledge time independently stored and queried. Source-authority hierarchy proposed but non-authoritative until product-owner approval (S17-G02).

### D. Deterministic compute

**Minimum deterministic compute (S16 · B-07, C-08 · Active; REQUIRED_NOW).** The **only authoritative calculator.** Owns the approved operator registry, typed `CalculationRequest`, immutable `CalculationTrace`. Operator families: GROWTH, MARGIN, CASH_CONVERSION, LEVERAGE, DILUTION_SHARE_COUNT, GUIDANCE_COMPARISON, RECONCILIATION. Replay classes: EXACT, TOLERANCE, STOCHASTIC. Invariants: *"The LLM may select or explain an operator but never supplies the authoritative result"*; `missing_input_policy` *"Always FAIL_CLOSED"*; `zero_denominator_policy` FAIL_CLOSED unless a typed `NOT_MEANINGFUL` result; *"No implicit unit conversion, currency conversion, annualization, sign flip, denominator choice, scope coercion, or restatement selection is allowed."* STOCHASTIC operators are outside the minimum list unless the spec is amended. Model-grade DCF/SOTP/WACC is **not** here (S21, deferred).

### E. Workflow, output & review

**Discovery-company vertical slice, manual baseline, bootstrap thesis (S05 · A-02, A-03, A-11 · Active).** Owns selection of one discovery company × four consecutive quarters (Q0 manual baseline + bootstrap thesis; Q1–Q3 assisted updates), the instrumented manual Q0 baseline, and the approved bootstrap thesis. Records: `DiscoverySliceManifest`, `BaselineInstrumentationEvent`, `ManualBaselinePackage`, `SourceConflictDisposition`, `BootstrapCoverageThesis`. Invariant: *"Approval applies to exact canonical artifact bytes … an agent draft never becomes the approved thesis."* Non-goal: does not automate full company initiation (DEF-01) or implement the assisted workflow (S14).

**Output, materiality & observable-falsifier contract (S06 · A-04, A-10 · Active; PROVISIONAL_V0).** Owns the output envelope, versioned materiality policy, falsifier structure. Records: `EarningsReviewOutputV0`, `CandidateClaimInventory`, `MaterialityPolicy`, `MaterialityDecision`, `ObservableFalsifier`, `MemoryDraft`. Output fields include event/cutoff, facts, changes, driver analysis, management ledger, thesis impact, observable falsifiers, open questions, calculations, memory draft, approval record. Materiality results: MATERIAL / NOT_MATERIAL / REVIEW_REQUIRED — *"`NOT_MATERIAL` … is not the default"*; always-material categories *"cannot be downgraded by a quantitative threshold alone."* Invariants: *"Every thesis impact contains at least one observable falsifier; generic risks and a no-falsifier approval or waiver do not satisfy the requirement"*; *"Memory drafts never write canonical thesis state. Output approval and memory promotion are separate human decisions."* Contract stage is `PROVISIONAL_V0`; `FINAL_V1` (final A-04) is forbidden until the A-03 baseline + A-11 thesis exist and the mandatory S06 amendment is re-reviewed.

**Fixed earnings-review workflow and feedback rework (S14 · B-01, B-02, B-14 · Active).** The first product workflow — a fixed, resumable state machine, not a planner. States: `REGISTERED → INGESTED → EXTRACTED → RECONCILED → CALCULATED → DRAFTED → HUMAN_REVIEW → APPROVED → PUBLISHED`. Human outcomes: ACCEPT, REJECT, EDIT, DEFER. Rework edges route from HUMAN_REVIEW (or post-APPROVED/post-PUBLISHED correction) back to the earliest affected step; evidence package `v(N+1)` is created, prior package immutable, only affected calculations/claims rerun. Records: `RunRecord`, `WorkflowTransitionRecord`, `StepAttempt`, `StepOutput`, `EvidencePackageVersion`, `PublicationTarget`, `PublicationEligibilityResult`, `PublicationReceipt`. Non-goal: *"Autonomous planning or arbitrary agent-selected workflow transitions."* Publication is gated to the current private/internal boundary — *"While E-08 remains deferred, public, paid, personalized, and execution-linked targets fail closed."*

**Human claim review, correction, supersession, promotion (S15 · C-05, C-10 · Active).** Owns claim-level review (accept/reject/edit/defer, source-jump, calculation inspection, diff-only review, memory-draft provenance, safe shadow mode) and the correction/promotion boundary. Records: `ReviewTask`, `ReviewDecision`, `CorrectionVersion`, `SupersessionRecord`, `PromotionRequest`, `PromotionDecision`, `PromotionReceipt`, `ArtifactMode` (PRODUCTION/SHADOW_TEST/GOLDEN_FIXTURE). Invariants: *"Claim/report acceptance and memory promotion are separate typed human decisions. Neither implies the other"*; *"`SHADOW_TEST` and `GOLDEN_FIXTURE` artifacts … cannot be promoted or published"*; promotion is *"all-or-nothing across canonical content and authoritative metadata"* (split-brain prevention). Doctrine: *"agents draft, validators attach QA, only the analyst promotes"* (`CONTEXT.md`).

**MVP universe, analyst-review economics, results-season throughput (S18 · B-04, C-01, C-12, C-18 · Active).** Owns Phase-0.5 review-economics measurement, Phase-1 universe selection (**exactly two or three core non-financial companies**), the Phase-1 economics gate, and peak-season throughput. Records: `UniverseCandidate`, `UniverseSelection`, `ReviewSession`, `ReviewActivityEvent`, `ReviewedClaimInventory`, `ComplexityDescriptor`, `BaselineMatch`, `CounterbalancePlan`, `EconomicsEvaluation`, `CapacityWindow`, `CapacityEvaluation`. Thresholds come from S08/A-13, not S18. Invariants: *"No report-level percentile is computed from the three assisted updates"*; *"Human acceptance cannot turn a mechanical threshold failure into `PASS`"*; financial-sector companies are excluded from the initial C-01 universe.

### F. Controls & measurement

**Golden set, failure taxonomy, reviewer-bias controls (S07 · A-08, B-08, B-13 · Active).** Owns the ≥20-case expert-labeled golden set, the failure taxonomy, and reviewer-bias/seeded-error controls. Records: `GoldenSetManifest`, `GoldenCase`, `FailureEvent`, `ReviewDecisionTelemetry`, `SeededDrillIsolationRecord`, `ExternalSpotReviewProcedure`. Failure codes: EXTRACTION, RECONCILIATION, SOURCE, UNIT, PERIOD, CALCULATION, CITATION, INFERENCE, REVIEW, CUTOFF_LEAKAGE, SOURCE_CONFUSION, DOCUMENT_AS_INSTRUCTION. Invariants: *"Source content is data, never control text"*; every golden fixture is *"non-promotable and non-publishable by lineage"* (`promotion_eligible`/`publication_eligible` fixed `false`); accepted-unchanged rate is not a standalone quality measure; clustered claims are not independent samples.

**Success metrics, budgets, operating capacity (S08 · A-07, A-12, A-13 · Active).** Owns one versioned metric catalog, per-workflow budgets, and the operating-capacity plan. Metric families: factual accuracy, citation correctness, numerical traceability, unsupported-claim rate, analyst minutes, per-claim verification time, coverage capacity, latency, cost, failure/retry rate. Records: `MetricDefinition`, `WorkflowBudget`, `OperatingCapacityPlan`, `MetricObservation`, `PhaseGateMetricBinding`. **This spec deliberately sets no numeric targets** — *"Numeric targets are evidence-derived and authority-approved values; this draft does not invent them."* Invariants: *"report-level P90 is forbidden at n=3"*; *"Quality controls do not trade off … favorable cost, latency, acceptance rate, or throughput cannot override unsupported claims, bad citations, missing traces, or required approvals"*; `CEILING_NOT_APPROVED` ≠ `NO_LIMIT` (null never means unlimited).

### G. Memory

**MemoryStore interface & conditional promotion transaction (S19 · D-01 active; D-03 Deferred · Mixed).** D-01 (REQUIRED_NOW): the engine-neutral `MemoryStore` port — `retrieve`, `stage_write`, `promote`, `correct`, `delete`, `export`. Records: `MemoryRevision`, `StagedWrite`, `PromotionRequest`, `CanonicalMemoryPointer`, `ProvenanceEnvelope`, `ExportManifest`. S19 *"does not choose GBrain or any other memory engine."*

**Model-grade financial compute (S21 · E-01).** DCF, SOTP, WACC, sensitivities, statement tie-outs, versioned sector definitions — after the S16 minimum layer. Dormant. `missing_input_policy` MUST be `FAIL`; LLM never calculates; outputs stay `computed`, never Fact/thesis. Broad sector-pack library is DEF-06.

**Stress-test-company expansion (S22 · E-02).** Bounded evaluation of whether the vertical-slice contracts generalize to one BANK_OR_NBFC, one CONGLOMERATE, one DIFFICULT_DISCLOSURE_OR_CORPORATE_ACTION. Dormant; no production universe, no bulk onboarding.

Multi-agent investment committee is DEF-04.

**Event monitoring (S24 · E-04).** Detection/normalization/dedup/routing/human-review of covered-company events. Alerts name which of six `affected_target` types changed — FACT, ASSUMPTION, CATALYST, PROMISE, FALSIFIER, THESIS_BREAKER. *"Detection does not equal approval"*; *"An `IMMATERIAL` event MUST have `proposed_thesis_diff_id=null` and MUST NOT invoke or satisfy the promotion path."* No trading, no auto-publish, no personalized recommendations. Portfolio construction is DEF-08; historical LLM alpha claims DEF-09.

## 4. Data model core

### 4.1 Key entities and identity rules

| Entity | Owner | Identity rule |
|---|---|---|
| **SourceDocument** | S09/S10 | Immutable object bytes; identity = `document_id` + `original_content_sha256`. Same URL + changed bytes = new occurrence; hash mismatch never overwrites. |
| **SourceOccurrence** | S12 | `source_occurrence_id` + digest; one immutable raw value at an exact location in one source version. *"Never overwritten."* |
| **ExtractionResult** | S12 | Parser/model or manual output for one exact occurrence + extractor version. A parser upgrade appends a new result. |
| **Observation** | S12 | Typed, normalized, **pre-reconciliation** value bound to exactly one ExtractionResult + its SourceOccurrence. Append-only. `observation_id` is never an alias for `source_occurrence_id`. |
| **MeasurementKey** | S12 | The economic slot: `entity + metric definition/version + period + statement/consolidation scope + dimension set + accounting/adjustment basis`. |
| **Fact (FactRevision + CanonicalSelection)** | S12 | A **reconciled** Observation for a measurement key. `CanonicalSelection` records which FactRevision is approved *"from one knowledge time"* via atomic compare-and-append. Not derived from newest/largest value. |
| **Claim (TypedClaim)** | S13 | Immutable version `claim_id`; subject–predicate–object with epistemic class + materiality; prose is display only. Material claims resolve to a fact ID, calculation trace, or exact source location. |
| **Evidence package** | S10 | Immutable `EvidencePackageManifest`; frozen per run attempt; any input change → `v(N+1)`; carries a complete `S12LineageClosure`. |
| **Calculation trace** | S16 | Registered inputs, assumptions, operator/code version, replay class, output; the only authoritative computed number. |
| **Run manifest** | S11 | `RunManifest`+`AttemptManifest`, immutable hash-chained versions; binds cutoff, inputs, tools, models, prompts, code, costs, QA, approvals, published-artifact hash. |
| **Memory record (MemoryRevision)** | S19 | `memory_id`+`revision_id`; status STAGED/CANONICAL/SUPERSEDED/DELETED; canonical pointer authoritative in SQL. |
| **Entity/Security master** | S17 | Stable, opaque, non-reusable internal `company_id`/`security_id`/`person_id`. ISIN/symbol/CIN/LEI are versioned external mappings, not the primary key. |
| **Correction chain** | S12/S08/S17 | Append-only supersession edges to a single current leaf; distinct revision reasons; *"no silent overwrite."* |

### 4.2 Relationships (which references which)

Acyclic content-addressed lineage (S12 → S10 closure): `SourceOccurrence` ← `ExtractionResult` ← `Observation` ← `RevisionFamily`/`ReconciliationDecision` ← `FactRevision` ← `CanonicalSelection`; `MeasurementKey` roots families/facts/selections. A `TypedClaim` (S13) links to fact IDs / calculation traces (S16) / source locations. An `EarningsReviewOutputV0` (S06) references facts, claims, calculation traces, falsifiers, a memory draft, and an approval record. An `EvidencePackageManifest` (S10) binds documents, the S12 lineage closure, claims, calculation traces, policies, approvals. A `RunManifest` (S11) binds one evidence package + attempt state under one cutoff. `MemoryRevision` (S19) binds source facts/claims/calc traces + evidence package; the `CanonicalMemoryPointer` lives in SQL. Entity/security IDs (S17) are consumed by measurement keys (S12) and calculations (S16).

### 4.3 Point-in-time / cutoff rules (S09, S11, S12)

- Every run fixes one immutable UTC `knowledge_cutoff` **before** any retrieval (S11). *"Every SQL query includes `knowledge_time <= :cutoff`."* Document/memory retrieval admits only versions whose first-seen/knowledge time ≤ cutoff.
- **Canonical selection is evaluated as of the cutoff** from S12's immutable linear chain: exactly one selection with `effective_from_knowledge_time <= cutoff` and no earlier-than-cutoff successor. *"A later restatement, correction, parser result, or policy change never rewrites a historical run."*
- `valid_time` (when a fact applies) and `knowledge_time` (when the system could know it) are stored independently; `first_seen_at` is never backdated (S09). Point-in-time capture *"prevents future loss; it is not a claim to have recreated unavailable historical data."*
- Downstream workflow stages consume one sealed evidence package and *"cannot fetch new evidence"* (S10/S11).

### 4.4 Retention (S10)

Corrections append; deletion is a distinct typed human gate (`DATA_RIGHTS_APPROVAL` / `LEGAL_REVIEW`) leaving a tombstone. Records referenced by an approved package/trace/review/approval/published artifact are **retention-pinned with their dependency closure** (including non-root SourceOccurrences/ExtractionResults). Derivative indices/caches may be dropped only when demonstrably rebuildable. *"Secrets, credentials, raw scratchpads, and document-originated instructions are never stored in an evidence package."*

## 5. Primary flows

Ordered end-to-end flows; **[H]** marks a human-in-the-loop gate.

**(a) Filing ingestion → point-in-time capture → evidence store (S02→S09→S10→S12).**
1. S02 confirms the source is approved for the exact use (else `UNKNOWN` → denied). 2. S09 acquires bytes under a current `AcquisitionAuthorization`; registers an immutable `SourceDocument` (hash, `first_seen_at`). 3. Daily/event jobs persist `CaptureEvent`s (prices, corporate actions, shareholding, membership, announcements) with hashes + first-seen times; failures persisted too. 4. Parse under a current `TransformationAuthorization` → append-only `ParseAttempt`. 5. S12 appends `SourceOccurrence` → `ExtractionResult` → `Observation`. 6. S10 pins retained records; evidence packages reference them by ID+digest. Gate: no post-cutoff or unapproved record may enter.

**(b) Discovery/company vertical slice (S05).**
1. **[H]** Product owner selects one discovery company + four consecutive quarters (`DiscoverySliceManifest`). 2. Manual Q0 baseline executed with instrumented `BaselineInstrumentationEvent`s; every fact resolves to a source or calculation trace at the declared cutoff. 3. Source conflicts recorded and dispositioned (`RESOLVED`/`EXCLUDED_FROM_BASELINE`) — **[H]** `ANALYST_ACCEPTANCE`. 4. **[H]** Analyst accepts the Q0 `ManualBaselinePackage`. 5. **[H]** Analyst authors + approves the versioned `BootstrapCoverageThesis` (thesis, assumptions, commitments, risks, open questions, observable falsifiers) — must exist before Q1. Gate: an agent draft never becomes the approved thesis.

**(c) Earnings review incl. rework (S14, consuming S06/S12/S13/S16).**
1. Register run under the prior approved thesis + one cutoff (`RunRecord`; genesis transition). 2. `INGESTED → EXTRACTED → RECONCILED` build/seal the evidence package. 3. `CALCULATED`: S16 deterministic operators produce traces (fail closed on missing/ambiguous inputs). 4. `DRAFTED`: agents draft typed claims (S13) into the `EarningsReviewOutputV0` (S06); every material claim resolves to fact/trace/source; every thesis impact carries ≥1 observable falsifier. 5. `HUMAN_REVIEW` **[H]**: analyst ACCEPT/REJECT/EDIT/DEFER. 6. On REJECT/EDIT: rework routes to the earliest affected step, creates evidence package `v(N+1)` (prior immutable), reruns only the affected closure, requires fresh **[H]** reapproval. 7. `APPROVED → PUBLISHED`: publication eligible only for a private/internal target (external modes fail closed while E-08 deferred).

**(d) Human review → correction → promotion (S15).**
1. `ReviewTask` binds exact reviewed bytes, evidence package, materiality/validator results, mode, provenance. 2. **[H]** `ReviewDecision` (ACCEPT with `ANALYST_ACCEPTANCE` only for PRODUCTION mode). 3. REJECT/EDIT → immutable `CorrectionVersion` + `SupersessionRecord` → S14 rework. 4. To change canonical thesis: a **separate** `PromotionRequest` → **[H]** distinct `MEMORY_PROMOTION` decision → one idempotent, all-or-nothing promotion transaction returning a `PromotionReceipt`. Gates: acceptance ≠ promotion; shadow/golden artifacts rejected server-side; split-brain prevented.

**(e) Memory promotion + benchmark (S19/S20).**
1. Approved narrative → `stage_write` (non-canonical) in the engine-neutral `MemoryStore` (S19). 2. `promote` requires exact-byte hash agreement, expected-prior compare-and-swap, and a current `MEMORY_PROMOTION` resolution; SQL holds the canonical pointer. 3. (Deferred/dormant) S20's three-arm benchmark + GBrain due diligence would inform a **[H]** `PRODUCT_OWNER_DECISION` on adoption at current scale only — not built in first release.

**(f) Run reproducibility (S11).**
1. Register run/attempt + immutable cutoff before any access. 2. Seal one evidence package; execute only registered steps against it. 3. Register calc traces, QA, costs, **[H]** approvals as new immutable manifest versions. 4. Bind approved artifact bytes by hash. Replay: exact-class operators reproduce exactly; tolerance/stochastic per policy; evidence package reconstructs by ID+hash; *"regenerated prose is a new artifact requiring review, not proof of reproduction."*

## 6. Controls & quality

**Golden set & reviewer controls (S07).** ≥20 expert-labeled cases including prompt-injection and source-confusion, plus seeded examples for wrong period/unit/source, unsupported claim, fabricated citation. `ReviewDecisionTelemetry` derives per-known-case outcomes (`CORRECT_*` / `FALSE_ACCEPT` / `FALSE_REJECT` / …) **stratified by materiality and epistemic class**. Seeded-error drills run only in `SHADOW_TEST`/`GOLDEN_FIXTURE` artifacts with promotion/publication eligibility fixed `false`, enforced *"in storage and at the server-side promotion/publication boundary, not only in the UI."* Manual and assisted instrumentation must be symmetric; Quarter 0 cannot be reused as an assisted quarter. Accepted-unchanged rate is explicitly **not** a standalone quality measure.

**Output materiality & falsifiers (S06).** Materiality combines quantitative magnitude, always-material categories (guidance, restatements, auditor qualifications, going concern, promoter pledges, related-party transactions, capital raises, material dilution, major corporate actions, management changes, regulatory actions), thesis relevance, and uncertainty/source conflict. Precedence is fail-closed: any always-material category → `MATERIAL`; unresolved conflict / missing input / important low confidence → `REVIEW_REQUIRED` (never `NOT_MATERIAL`). Every thesis impact needs ≥1 observable falsifier naming the event/metric/management outcome/evidence that would `MATERIALLY_WEAKEN` or `REVERSE` the thesis.

**Success metrics, budgets, capacity (S08).** Ten metric families (§3-F). Budgets use `MEASUREMENT_RULE` or `CEILING` controls; `CEILING_NOT_APPROVED` ≠ `NO_LIMIT`. **No numeric thresholds are set in-spec** — they are evidence-derived and human-approved (A-13). `MetricObservation` correction chains have one current leaf per scope. Quality controls do not trade off against cost/latency/throughput. Report-level P90 forbidden at n=3; clustered claims are not independent samples (also S18).

**Quant validation & leakage rules (S25, deferred).** Minimum `LeakageFinding` categories: future-knowledge, revision/restatement, survivorship, universe-selection, target, feature, corporate-action, source-availability, label, split/embargo, analyst-memory, repeated-holdout, model-weight. Two disjoint control classes: `CONTROLLABLE_STORE_OR_TOOL` (tested — the cutoff enforcement of S11/C-15) vs `UNCONTROLLABLE_MODEL_WEIGHT` (a standing disclosure that *"cannot be eliminated"*). E-05 must disclose fees, liquidity, benchmark, revisions, universe history; missing/defaulted assumptions → `BLOCKED`. `PASS` means only the frozen validation rule passed — *"not clean alpha evidence or production, causal, regulatory, distribution, or investment approval."*

**Thresholds actually quoted anywhere:** none numeric — the specs deliberately defer all numeric targets to human-approved, versioned contracts (S08/A-13, S18). Do not invent numbers in the artifact.

## 7. External dependencies

**Providers & data rights (S02).** Every source needs a `SourceRightsRecord` across ten independent dimensions; *"Permission to access does not imply automation, caching, retention, commercial use, derived-output, or redistribution permission"*; *"Private/internal permission does not imply public, paid, personalized, or execution-connected permission."* Missing/ambiguous → `UNKNOWN` → denied. **Consensus estimates are excluded by default** (C-13) unless proven *"licensed and necessary"* (DEF-07). No agent performs purchase, provider contact, credential access, or external enrollment — each needs a distinct human approval.

**External tools (S03).** OpenBB (E-06) and FinanceHarness/Vibe-Trading (E-07) are dormant; only structural due-diligence gates exist. No cloning/install/network/provider contact in this draft. Any adoption is a separate `ExternalToolAdoptionDecision`; OpenBB, if adopted, runs out-of-process behind an Equity-OS adapter and still passes S02 rights gates.

**Model / LLM usage rules.** The LLM is **never the authoritative calculator** (S16: *"The LLM may select or explain an operator but never supplies the authoritative result"*); numbers come from registered deterministic code with traces. LLM judgment is confined to non-authoritative roles: drafting claims/narrative, extraction, classification, explanation, operator selection — all subject to human review and typed evidence. Retrieval/prose *"cannot convert one class into another"* (S06/S12/S19). Model-grade compute (DCF/SOTP/WACC, S21) is deferred and, when active, still *"never … an authoritative calculator or hidden input."* Historical LLM output carries a mandatory model-weight-leakage disclosure and is never clean-alpha evidence (S25). Model/vendor bindings live only in `CONTEXT.md`'s role table, not in specs.

### 10.1 The three open human-review items (HR-0001/0002/0003)

## 11. Glossary (use consistently; from CONTEXT.md)

1. **Equity-OS** — the product/repo: a persistent, evidence-governed equity-research system, not an autonomous stock-picking chatbot. (Avoid "Funda" except when citing the blueprint.)
2. **Blueprint** — the approved reference set in `docs/blueprint/` (strategy reference, not the build spec).
3. **Decision register** — the single operational source of truth for decisions/gates (v2, IDs A-01…E-10); its wording is authoritative for implementation gates.
4. **Blueprint phase** — a delivery stage (0A, 0.5, 1, 2, 3+) with an exit gate.
5. **Vertical slice** — Phase 0.5: one discovery company across four consecutive quarters (Q0 manual baseline + bootstrap thesis; Q1–3 assisted updates).
6. **Discovery company** — the single company chosen for the vertical slice (A-02).
7. **Earnings-review workflow** — the first product workflow: a fixed, resumable state machine, not an autonomous planner.
8. **Observation** — a typed, extracted, normalized, **pre-reconciliation** value (raw + normalized, units, currency, scope, dimensions, source location, temporal fields).
9. **Fact** — a reconciled observation in the append-only, revision-aware SQL store; restatements supersede, nothing silently overwritten.
10. **Claim** — a typed assertion (subject, predicate, object, scope, horizon, epistemic class, confidence, status, supersession); prose is display only; material claims resolve to a fact ID / calculation trace / exact source location.
11. **Epistemic class** — the mandatory output label: observed / computed / inferred / forecast / opinion.
12. **Evidence package** — the frozen set of documents, facts, and calculations a run works from; built once per run; downstream steps do not fetch new evidence.
13. **Valid time / knowledge time** — the bitemporal pair: when a fact applies vs when the system could have known it.
14. **Point-in-time capture** — daily/event persistence of membership, prices, announcements, corporate actions, shareholding with hashes and first-seen times; prevents future loss, does not recreate the past.
15. **Source-of-truth hierarchy** — the authority table (immutable object store; SQL for facts/claims/events/approvals; registered calculation store; versioned Markdown narrative; rebuildable indices).
16. **Deterministic compute** — registered, traceable calculation code; the only authoritative calculator. (The LLM never is.)
17. **Calculation trace** — the registered record of inputs, assumptions, outputs, and code version behind a computed number.
18. **Thesis** — the current approved analytical view of a company; versioned narrative, never "current truth," never a recommendation.
19. **Management ledger** — the tracked record of management promises (new/modified/due/outcomes).
20. **Memory promotion** — the separate, human-approved action that lets a drafted change affect the canonical thesis (agents draft, validators attach QA, only the analyst promotes).
21. **Golden set** — the owned, expert-labeled evaluation fixtures (~20 to start), grown from observed failures.
22. **Analyst review economics** — the headline product metric: analyst minutes per approved update, accepted-unchanged rate, correction categories, source-location time.
23. **Distribution boundary** — the hard gate between private/internal research and any paid/public/personalized output (regulatory, not stylistic).
