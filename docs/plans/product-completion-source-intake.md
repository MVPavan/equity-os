## Trust and integrity contract

The trusted actors are the local operator, installed producer code, UTC system clock and store-owned filesystem. Untrusted inputs include capture JSON, CLI reference manifests, claimed acquisition dates, source contents and model output. The operator selects the existing approved store and approved source/configuration scope; an arbitrary directory supplied by source content is never promoted to an authoritative store.

Use a metadata-only ledger under the existing SnapshotStore root: `.source-intake/<binding_id>/installed.json` and `registration.json`, with one store-owned lock. Originals remain solely in the existing capture/blob layout. The registration subtree is mode 0700, records/lock mode 0600, owned by the trusted operator account; refuse symlinks, nonregular records, wrong owner or group/other write permission. Open the root and descendants with anchored directory descriptors and no-follow component traversal. Model execution and source parsing have no registration/write tool. Same-account arbitrary filesystem access is trusted-operator power, not a model-facing capability.

The ledger is authoritative because only the trusted producer writes this protected subtree. Its canonical SHA-256 detects corruption and pins the receipt; a self-consistent hash does not authenticate a document from elsewhere. There is no receipt import, registration JSON argument, caller clock, date flag, permission-string override or fallback to capture timestamps. Forging an old capture with valid hashes cannot create a ledger receipt. Direct rewriting of all authoritative storage by a malicious administrator is outside this contract; do not claim protection against it.

Registration does not grant source rights. Add a narrow frozen runtime `ApprovedIntakeBinding(role, source_id, expected_sha256, rights)` and `ApprovedIntakeContext` in `api/source_intake.py`. The context holds exactly the three bindings for the selected approved quarter/configuration, its approved configuration-byte SHA-256, and the operator-selected protected store and local-input directory handles. It has no timestamp fields, wildcard grants or source-discovery behavior. Trusted root constructs the runtime `SnapshotRights` representation of the existing approved A05-DECISION-004 source-use scope: `private_internal`, redistribution prohibited, and the exact vetted source-use authority references. No prior Apar serialized `SnapshotRights` instance is required or claimed to exist. Registration and replay compare every rights field and the complete ordered reference tuple against that root-supplied representation. This is a composition input, not a serialized approval contract, registry or permission policy.

**Origin and injection:** The trusted local operator/root reuses the existing exact-byte Apar approval context: source IDs and PDF content pins from the selected unchanged `config/aparinds-*.yaml`; the selected quarter's XBRL content pin from the already operator-accepted `docs/evidence/phase-0.5/apar-retrieval-manifest.json` entry; and the runtime rights representation of the existing A05-DECISION-004 source-use scope described above. A02-ATTEST-002 supplies suitability for the exact Apar slice separately; it does not supply source-use authority. `XbrlConfig` has no expected hash, so neither it nor the registration input manifest supplies that trusted pin. Root verifies the selected artifacts against its existing accepted versions and supplies the resulting in-memory context to the installed producer. These filenames/decision strings and a newly computed file digest do not authenticate approval by themselves. Source/content/configuration bindings come from root's independently vetted accepted context. Missing genuine authority or vetted bindings yields `NEEDS_CONTEXT`; absence of an old serialized rights instance does not. Do not derive authority from the record being registered or invent a substitute string.

The proposed narrow runtime seam is `main(argv, *, intake_context: ApprovedIntakeContext | None = None)`. An installed operator-controlled local launcher/direct composition calls it with the context above; ordinary `main(argv)` remains valid but refuses `register-sources` and registration-backed native resolution without context, before writes or source parsing. The same context is supplied to `SourceIntakeStore` and staging, and is explicitly reconstructed from the same existing accepted versions by root after restart. No argv option, environment variable, JSON context file, dynamic plugin or manifest field selects/creates this object. External model input may provide only untrusted locators for comparison; it has neither this launcher/write capability nor access to its accepted-context construction. Arbitrary same-account Python/filesystem execution remains trusted-operator power outside this boundary. Synthetic public-main tests inject a synthetic context through the keyword seam, never through argv. Native reopening compares the receipt and capture to the injected bindings too. Successor evaluation acceptance remains a separate human decision; this source context cannot authorize a changed evaluation contract.

## Minimal contracts and durable ordering

Create `contracts/source_registration.py` with frozen, extra-forbid `SourceRole` (`xbrl`, `results_pdf`, `transcript_pdf`), `SourceRegistration`, and typed `SourceRegistrationError`. A registration contains schema version 1, the six existing reference coordinates/hashes, role, `capture_completed_at`, `first_observed_at`, `registered_at`, and canonical receipt digest. Keep original `CaptureRecord.retrieved_at` unchanged as an acquisition **claim** bound by `record_sha256`; display it separately in audit. No new publication/authority fields are needed.

`binding_id` is SHA-256 of canonical four lookup coordinates. One slot per capture prevents rebinding its role, record hash or source hash. Identical registration requests return the original receipt and clocks only after re-verifying current bytes. Different role/hash for that slot is conflict; identical bytes at different coordinates establish a separate current registration, never inherit another capture's time.

New `SourceIntakeStore(snapshot_store, *, approved_intake: ApprovedIntakeContext)` exposes `register_capture(*, role, source_id, surface, request_key, capture_id, source_sha256, record_sha256) -> SourceRegistration` and `get_registration(...) -> SourceRegistration`. Neither accepts timestamps or caller rights. An internal verified-resolution method returns the receipt and pinned original bytes together. Every operation compares role, source ID, content SHA-256 and exact record rights to the injected binding; coordinates/record digest remain untrusted lookup pins requiring independent verification. The trusted producer uses actual UTC; synthetic tests control its module clock, not a production API parameter.

**Explicit local representation:** Narrowly extend `RequestMethod` with `LOCAL_READ = "LOCAL_READ"`; retain GET/POST values, GET default, request schema version, canonical serialization and existing hashes. Local staging explicitly sets this method, a fixed `local_<role>` surface, a request key derived from role/content SHA-256 and empty parameters (no private pathname). After bounded EOF and hash verification, sample actual UTC for `retrieved_at`, meaning this local read, and construct `BlobRef(source_id=binding.source_id, content_sha256=binding.expected_sha256, byte_count=len(body))` plus `OutcomeRecord(code=OutcomeCode.OK, native_kind="LOCAL_READ", native_value="complete")`. Call `CaptureRecord.make` with `schema_version=CAPTURE_SCHEMA_VERSION` (2), `body_completeness=BodyCompleteness.COMPLETE`, `body_read_issue=None`, `http_status=None`, `content_encoding=None`, role media type (`application/xml` or `application/pdf`), the verified blob and exact context rights. Use its existing derived capture ID; no new CaptureRecord fields or serializers. Registration's later verified-store read supplies its completion/observation clocks. Existing network captures retain their actual methods/statuses unchanged.

**Descriptor and durability primitives:** Pin the protected pre-existing store root and its parent from the trusted operator anchor; verify ownership/modes and directory identity throughout. Traverse plain components using directory descriptors, `O_DIRECTORY|O_NOFOLLOW`, and descriptor-relative operations. Stage-local input, record, blob, receipt, manifest and lock reads first refuse nonregular entries via descriptor-relative no-follow stat, then open with `O_RDONLY|O_NOFOLLOW|O_NONBLOCK`, immediately `fstat` and require a regular file before any read. A stat/open substitution to FIFO/socket/device/directory must refuse without waiting for data; no blocking ordinary `open` fallback. Enforce 32 MiB body/64 KiB metadata limits with bounded chunks and cap-plus-one EOF detection, including growing files; use a five-second monotonic read budget and refuse expiry. This assumes the trusted local filesystem's regular-file syscall behavior, not a hard deadline for a hung kernel/storage device.

`put_capture(record, body)` keeps its public API and existing original layout but its staging writer must use pinned descriptors for route/blob/staging creation, exclusive temporary files, no-clobber file links and final directory publication. No mutation may reconstruct a pathname after checking an ancestor. Protect the publication with a store-owned writer lock used by every `put_capture` writer; refuse any existing final entry, then rename through source/destination directory descriptors while holding the lock. Identical existing captures require byte verification; conflicting/orphan destinations are never overwritten. The protected operator-owned ancestry excludes noncooperating same-account writers; descriptor pinning prevents ancestor substitution from redirecting writes, and post-publication reachability/identity checks refuse detached/replaced ancestry. Extend race proofs through blob creation, staging links, record publication and final rename, not only reads. Do not alter shared `no_clobber.py`; replace pathname helper use inside this writer with local descriptor operations.

For every directory created via a parent descriptor, open/verify the child, fsync the child, then fsync its parent to persist the new name before descending or treating the hierarchy as durable. Cover root entries for source routes, `blobs`, `.staging`, `.source-intake`, lock publication, every source/surface/request-key/capture/blob-prefix/binding directory and staging child. Fsync each new file before no-clobber publication and its containing directory afterward; hard-linked blob/body entries require their destination-directory fsync. Before final capture rename, fsync blob data and its directory chain plus staging record/body and staging directory; afterward fsync both destination route and source `.staging` descriptors and verify the resulting capture. Before `registered_at`, re-verify/flush the complete referenced original files and authoritative ancestry, the ledger ancestry and installed binding. Reopen/idempotency cannot assume an existing name was durably published: verify and fsync files, children and each parent entry through the pinned root/parent, including both rename parents where relevant. Unsupported fsync or any boundary failure refuses durable success.

1. Acquire the store-wide descriptor-based exclusive lock with a five-second monotonic deadline; timeout refuses, without automatic retry. Resolve the exact capture with a new secure bounded SnapshotStore read. Require exact route/record/body source identity, both hashes, `OutcomeCode.OK`, a nonempty COMPLETE body and exact role/source/content/rights agreement with the injected approval context. PARTIAL, ABSENT, failed outcome and OK_EMPTY refuse, even when their bytes parse. Reject unknown capture schemas. Legacy effective COMPLETE alone is not EOF proof: root must re-stage a complete local original as v2 before registration; an old explicit-v2 complete capture may undergo current verified intake.
2. The secure read returns one immutable buffer. After its complete read sample `capture_completed_at`; after hash, identity, outcome and role verification sample `first_observed_at`. For imported captures these mean completion and first observation of **this local intake**, not original network acquisition. Stage-local production similarly stamps completion after reading, never before it. Refuse non-UTC/naive or backward clocks; never clamp or backdate.
3. Persist all originals and new parent entries by the descriptor protocol above. Publish `installed.json`, containing the exact binding and role, using an exclusive temporary file, file fsync, atomic no-clobber link and binding-directory fsync; `.source-intake` and binding names must already have their parent fsyncs. This is the durable installation of a verified source binding. Only **after** all these original/ledger flushes succeed sample `registered_at`, bounded below by the two observations. Thus the registered bound cannot precede durable binding installation. It does not describe the later receipt-file write time.
4. Publish the immutable receipt with the same no-clobber/fsync sequence. Eligibility requires both files and exact agreement; installation alone is unavailable to admission. Receipt persistence records the already-completed installation observation. Return success only after receipt, directory and all required parent-entry fsyncs. Crash before receipt publication leaves no admissible proof; orphan reopening repeats byte/context verification and flushes original/ledger files and ancestry, generates current clocks after those flushes and preserves the installed binding. Crash after publication may leave a valid receipt; reopening verifies it and flushes the entire referenced publication before an idempotent success with unchanged clocks. No mtime or preexisting-name shortcut. An I/O failure never returns success.
5. Release the lock. Reopening reads only fixed-size receipt/binding records and exact referenced originals; no tree-wide scan or mtime inference. Check receipt digest, installed binding, clock order, current UTC ceiling and bytes again. Corruption/missing proof refuses without repair or overwrite. Maximum source size is 32 MiB per role; metadata/manifest cap is 64 KiB, with at most three references. Oversize refuses; limits cannot be raised by JSON/CLI. This bounds producer-owned buffers, not total parser RSS.

Use the existing local filesystem's fsync/atomic-publication assumptions. Receipt hashes and modes do not protect against malicious trusted-operator rewrites. When a protected store cannot be established, return the precise unsafe path/ownership error; do not downgrade to untrusted metadata.
